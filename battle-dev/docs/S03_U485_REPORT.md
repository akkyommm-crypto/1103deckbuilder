# S03-U485 — 《暗黒界の龍神 グラファ》②: 破壊できなかった場合は手札確認を行わない

ユーザー裁定（2026-10-30、選択肢①）に基づく。U483 が再現まで行い、裁定の衝突で保留していた項目。

## 1. 裁定と、根拠の性質の違い

**この 2 点は根拠の種類が違うので、区別して記録する。**

### (A) 対象がいなくても強制の誘発はチェーンに載せる — 現状維持
根拠は**他カードの当時 FAQ からの採用判断**で、グラファ自身の回答ではない。

- `WIKI-AA425BA7DAF5`（NEPTUNE、2009-12-29）: 強制の誘発は対象がいなくても発動し、チェーンブロックが作られる
- `WIKI-6C057DCC8B74`（ヴァンダルギオン、2005-03-14）: 対象がいない場合は、発動して不発になる

現行の挙動（対象 0 でもチェーンに載る）が正しいので、**変更していない**。
現行公式の扱い（対象がなければ発動しない）は 1103 の開発方針として**採用しない**とユーザーが決定した。

### (B) 破壊できなかった後の手札確認は行わない — 修正した
根拠は**グラファ自身の FAQ**。

- `WIKI-9A95D36090C4`（2011-06-18、`verdict: cannot`）
  - Q: 相手によって捨てられた場合の効果の処理が、対象に選択したカードが存在しなくなり破壊できなかった場合、ランダムに手札を確認する処理は行いますか？
  - A: **いいえ、行いません。**

補強（同ページ・同日）:
- （2011-06-18、`cannot`）相手フィールド上のカードの破壊と、相手の手札の確認は同時処理ですか？ → **いいえ、破壊してから確認するため別のタイミングとして扱います。**
- （2011-06-18、`can`）相手によって捨てられた時、ランダムで確認するのは強制。確認したのがモンスターだった場合、特殊召喚するかどうかは任意。
- （2011-06-22、`conditional`）確認したのが特殊召喚できないモンスターの場合、特殊召喚する処理は行われず手札に残る。

出典は `1103_SHARED/1103_rulings_complete_v8_154.zip` の `wiki-rulings.js`（2011-08-31 以前の Wiki バックアップ）。

## 2. 修正前の挙動

`cards/20_control_counter.js` の `resolve`:

```js
if(r && r.p===ctx.opponent) API.destroy(r, "暗黒界の龍神 グラファ");
if(darkWorldDiscard(ctx)==='opponent') graphaPeekHandS03(ctx.player, ctx.opponent);
```

手札確認が**破壊の成否と無関係**に行われていた。対象が最初からいない場合（`selectTargets` が `done([])`）でも、
対象が解決前に場を離れた場合でも、破壊が身代わりに置き換わった場合でも、手札確認まで進んでいた。

## 3. 修正

破壊が実際に行われた時だけ手札確認へ進む。判定は **S03-U294 の continuation**（`engine/1ZZO_destroy_after_s03.js`）で行う。

```js
if(r && r.p===ctx.opponent){
  const mark = API.destroyMarkS03(), uid = ensureCardUid(gameState, r.card);
  API.destroy(r, "暗黒界の龍神 グラファ");
  if(darkWorldDiscard(ctx)==='opponent')
    API.afterDestroyS03('s03u485.grapha-peek', {player:ctx.player, opponent:ctx.opponent, mark, uids:[uid]});
}
```

```js
registerDestroyAfterS03('s03u485.grapha-peek', a=>{
  if(!API.destroyedSinceS03(a.mark, a.uids).length) return;   /* 破壊できなかった → 手札確認は行わない */
  graphaPeekHandS03(a.player, a.opponent);
});
```

**同期的に判定してはいけない理由**: 任意の破壊身代わり（S03-U173、`destroySubstituteS03`）があると、
その解決中の破壊は身代わりの選択が終わるまで保留される。`API.destroy` の直後に盤面を見る実装では、
選択前の盤面を見てしまう（S03-U173 の既知の制限）。U294 の continuation は「保留が無ければ即時、
あれば選択と保留された破壊の後」に走るので、両方で正しい。

変更は `cards/20_control_counter.js` だけ。エンジンには手を入れていない。

## 4. 試験

`tools/test_s03_u485_grapha_peek_after_destroy.js`（**23 PASS / 0 FAIL**）。`tools/check.py` と `tools/script_coverage.py` に配線済み。

実経路（相手が伏せた《手札抹殺》で自分の手札のグラファを捨てさせる）で駆動し、全ケース Replay 監査つき。
手札確認の有無は Journal の `GRAPHA_PEEK_S03` Action の数で見る（乱数は Action の中で引かれる）。

| ケース | 内容 | 期待 |
|---|---|---|
| A | 対象を普通に破壊できた | 手札確認 **1 回**（破壊できた場合の挙動は変えていない） |
| B | 相手の場にカードが無い | 強制の誘発は**チェーンに載る**（(A) の裁定、Journal の CHAIN_ADD で確認、対象 0 枚）が、手札確認は **0 回** |
| C | 対象が解決前に場を離れた（相手が《強制脱出装置》をチェーン） | 手札確認 **0 回**。裁定の文言そのままの場合 |
| D | 破壊が身代わりに置き換わった（《真六武衆－シエン》→ 別の六武衆を破壊） | シエンは場に残り、手札確認 **0 回**。破壊の成否を選択の後に判定している証拠 |

自分の効果で捨てた場合に②も手札確認も起きないことは、既存の
`tools/test_s03_u125_dark_world_targets.js` の B（《暗黒界の門》による自分の捨て）が既に固定しているので**二重に実装していない**。

### Negative control

修正前の `resolve`（破壊の成否を見ずに手札確認へ進む版）を実行時に入れ直すと、**B・C・D のすべてで手札確認が 1 回行われる**。
B・C・D の PASS が「そもそも手札確認が起きない盤面だから」ではなく、この修正によるものだと示している。
