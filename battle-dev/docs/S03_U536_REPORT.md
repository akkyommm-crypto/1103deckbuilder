## 1. 当時裁定から組み立てたもの（推測していない）

- `WIKI-C713005AECCE`（08/03/04）リバース効果なので**強制的に発動**する → `forced:true` + `passive.onFlip`。
- `WIKI-EE7F0FD9C805` 破壊が確定している場合、この《カオスポッド》自身はデッキに戻さず、戻した枚数にも
  数えない → engine の共通判定 `battleDestroyConfirmed`（`card.battleDestroyed`）が立っているカードを
  戻さない。リバース効果はダメージ計算後に解決し、戦闘破壊はその後の `BATTLE_CLEANUP` で適用されるので、
  解決時点では「破壊が確定して場に残っている」状態になる（D1 で実測）。
- `WIKI-40865A68CC06` 持ち主の異なるモンスターは**元々の持ち主のデッキ**に戻り、その持ち主の枚数として数える
  → 戻した後の位置（`returnToOwnerDeckOrExtra` / `cardOwnerIndex` の結果）を**見てから**数える。予測しない。
- `WIKI-181C35842ACF` 融合モンスターは融合（EX）デッキに戻るが「デッキに戻ったモンスター」には数えない
  → 戻った後のゾーンが `deck` のものだけを数える。
- `WIKI-48E1E4F372AF` 罠モンスターはデッキに戻るが、戻る時点で罠カードとして扱うので数えない
  → 戻った後の `dbOf()`（`reset()` が `asMonsterDbS03` を外す）が `k==='m'` のものだけを数える。
- `WIKI-8525D514E977` モンスタートークンはデッキに戻らずその場で消滅し、数えない
  → engine の `FX_RETURN_DECK` がトークンを消滅させる。戻り先が無いので数に入らない。
- `WIKI-330E11853767` 一枚も戻せないならカードをめくる必要が無い → 数が 0 のプレイヤーはめくらない。
- `WIKI-2C139A4EDD50` 特殊召喚できないモンスターや上級モンスターは墓地へ送られるが、**めくった数には数える**
  → めくる処理は「モンスターが出た数」で止め、出せないものは `API.mill` で墓地へ。
- `WIKI-9D5344BF8AAD`（10/08/27）《大熱波》等で特殊召喚できないモンスターも墓地へ送られる
  → 1 体ずつ engine の判定（`canEffectSpecialSummonS03` と `API.specialSummon`）に通す。
- `WIKI-D0DA5D38F294` 特殊召喚できる数を超える場合は出すカードを選び、残りのレベル 4 以下は墓地へ捨てる
  → 空いているモンスターゾーンの数を超えるときだけ、**そのプレイヤー自身**に選ばせる（`ChoiceRequest` の
  `player` をそのプレイヤーにする。登録ハンドラ経路なので保存・再開・Replay を跨げる）。
- `WIKI-053C741FA707` この効果で裏側守備表示で特殊召喚したモンスターの表示形式はそのターン変更できない
  → `{faceDown:true}` が `summonedTurn` を記録する（S03-U136 と同じ経路）。

## 2. 実経路で測ったこと

`tools/test_s03_u536_chaos_pod.js`（16 PASS）。Replay 監査は 6 場面。

- A1: 登録、強制のリバース効果 1 つ、継続ハンドラ `s03u536.pick` の登録。
- B1: 反転召喚。自分の 2 体・相手の 1 体が持ち主のデッキに戻り、自分は 2 枚・相手は 1 枚めくって、
  全て**裏側守備表示**で特殊召喚される（`summonedTurn` が記録される）。
- C1: コントローラーが自分・持ち主が相手のモンスターは**相手のデッキ**に戻り、相手の枚数 1 として数えられて
  相手がめくる。
- C2: negative control。融合モンスター《紅陽鳥》は EX デッキに戻り枚数に数えないので、めくるのは 1 枚だけ。
- C3: 相手がめくったレベル 6 の《デーモンの召喚》は特殊召喚されず墓地へ送られる（めくった数には数える）。
- D1: negative control。戦闘で破壊された《カオスポッド》自身は墓地にあり戻らず、戻った数が 0 の相手は
  **めくらない**（デッキが減らない）。
- E1: 6 体が自分のデッキに戻って 6 枚めくるが、空きは 5 なので 5 体を選んで出し、残り 1 枚は墓地へ捨てる。

関連テストも通過: `test_s03_u451`（裏側守備表示の特殊召喚と両者の選択）・`test_s03_u136`・
`test_s03_u248`（罠モンスター）・u533・u534・u535。

## 3. 未対応・後続課題

1. `WIKI-A9AAB0C03493`（07/12/10）デッキが空で無限ループになる場合、ジャッジに証明した上で効果処理を
   行わない → ジャッジの介入は実装できないので**未対応**。デッキが空のときは「めくるカードが無い」として
   そのまま処理を終える（無限ループは起きない）。
2. `WIKI-48E1E4F372AF`（罠モンスターは数えない）は、戻った後の `db` が罠カードになる経路で実装しているが、
   罠モンスターを場に出す実装済みカードでの**実測は未了**。
3. `WIKI-8525D514E977`（トークンは消滅して数えない）は engine の `FX_RETURN_DECK` の既存処理に乗っているが、
   トークンを含む盤面での**実測は未了**。
4. `WIKI-9D5344BF8AAD`（《大熱波》で特殊召喚できない場合）は判定経路（`canEffectSpecialSummonS03`）に
   乗せているが、《大熱波》自体での**実測は未了**。レベル 6 のモンスターが墓地へ送られる経路（C3）で
   「出せないものは墓地へ」だけを測っている。
5. `WIKI-CF642F23F1C8`（11/08/03）デッキをめくる処理があるため、フィールドを離れた時の任意効果は
   タイミングを逃す／めくる処理を行わない場合は**調整中** → 当時「調整中」の裁定なので**未確定**として記録する。
6. めくったカードを相手に見せる処理は、ログに枚数を出すだけにしている（公開情報の持ち方は engine 側の
   課題。S03-U522・U527 と同じ）。
7. `WIKI-EE7F0FD9C805` は《カオスポッド》自身についての裁定だが、実装は「破壊が確定している**モンスター**は
   戻さない」と一般化している（engine の `battleDestroyConfirmed` は「確定後は永続効果を出さず効果の対象にも
   取れない」という共通の扱いを既に持つ）。自身以外のモンスターについては当時裁定を確認できていないので、
   この一般化は**未確定**として記録する。
8. 《サイバーポッド》は同じ系統だが `ENGINE_GAP`（1 体ごとの表示形式の選択が必要）のままで、この単位では
   触っていない。
