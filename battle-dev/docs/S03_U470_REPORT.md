基点: `claude/work` `b82d52bf`（U469）。Sonnet 5.5、単一ライター。**part C のみ**（カードの `condition` と回帰テスト）。共有エンジン（part B: 選択APIから発動準備への「候補不足」の明示、単一の中止処理、状態復元）は本単位に含めない。`engine/` は無変更。

## 基点の実測
`git archive b82d52bf` のクリーンコピー（`battle-dev` のファイル一覧は追跡ファイル2187件と完全一致）で直列 `python tools/check.py`: **22329 PASS / 0 FAIL / 0 Traceback・ReferenceError / `GATE_EXIT=0`**、末尾 `PASS no duplicate top-level function declarations`。U469 の実測と一致。（`TypeError` 1件は基点ゲートにもある `test_auto_cycle32.js` 冒頭の記録済み1件。）ログ: scratchpad `gate_base.log`。

## 診断（依頼どおり。再現して確認済み）
原因は「候補が0になる」ことではなく、**スクリプトの `condition`（生のプール確認）と `filterTargetable`（対象耐性）の間のずれ**。
`condition` が生のプール（「墓地にモンスターがいる」）で通る → 発動が始まりカードが表になる（`engine/30_processor_chain_battle.js:1442` `FX_SET_STATE face:'up'`）→ 対象選択が `filterTargetable` で全候補を失い、`requestChoiceV49` が「選択できるカードが足りません」で `false` を返す → 継続（`finishPrepare()` も `opts.onAbort`）が呼ばれない → 魔法・罠ゾーンに表で残り、チェーンも選択も無い。
再現（`リビングデッドの呼び声`、P0=サイバー・ドラゴン+メタルシルバー・アーマー、P1=墓地にモンスターのみ）: 修正前 `{chain:0, sz:1, face:up}`、トースト「選択できるカードが足りません」。コントローラー自身の発動（対照A）・耐性なし（対照）は正常、墓地が空（対照B）は元から断られていた。

## 範囲と調査方法（「再現確認済みの主要カード」）
- **対象の母集団**: `selectTargets` / `targets:true` を持つ魔法・罠 969 枚。使い捨てスクリプト（scratchpad `survey/fuzz*.js`）で、P1 が相手の免疫の下で各カードを発動する盤面を作り、「発動が始まったが、チェーンも選択待ちも無く、カードが表で魔法・罠ゾーンに残った」を **STUCK** と判定した。免疫を外した同一盤面（対照）でも STUCK になるものは除外（免疫が原因のものだけを数える）。
  - 盤面A: メタルシルバー・アーマー（P0、サイバー・ドラゴンに装備）。相手の効果は、お互いの場・墓地・除外のモンスター（装備モンスター以外）を対象にできない。
  - 盤面A2: 盤面A + 主要デッキ素材（P1の場に六武衆・TG・爬虫類・デュアル・鳥獣、墓地にE・HERO通常・六武衆・TG）。
  - 盤面C: 両者の場が オベリスクの巨神兵 だけ（自身のテキストで効果の対象にならない。場のモンスターを対象にする全カードの共通の露出）。
  - 免疫源は、墓地・除外ではメタルシルバー・アーマーだけ（U468）。場のカードを対象にするカードは多数の免疫源に露出する。墓地を対象にするカードの露出はアーマー1枚に限られる。
- **結果**: 免疫が原因の STUCK は **延べ134枚**（A: 61、C: 75、A2: 68、重複あり）。これは「数枚」ではないため、**主要の基準を客観的に決めた**: プロジェクト固定の主要デッキ13本（`data/r1_lists/major_decks_v1_*.txt`、完全一致で解析）に入っているカード。
- 加えて、盤面では条件を満たせない主要デッキのカードは、素材を足した個別盤面（`survey/targeted.js`）で再現を試した。

- 盤面では自身の前提（融合モンスター・素材、TG の場、特定の手札など）を満たせず発動不可で、免疫との関係を確認できなかった: 超融合、ミラクル・フュージョン、簡易融合、TG1－EM1、デュアルスパーク以外の前提つきカード（**「露出しない」とは言えない。未確認**）。
- 次元幽閉: 攻撃宣言の窓が必要。さらに `cards/00_generic_core.js` の定義に `targets:true` が無く、`selectCard` の `targeting` が立たないため**対象耐性自体が掛からない**（STUCK にはならないが、別の欠陥として耐性を無視する）。本単位では触らない（記録のみ）。

## 前提の訂正（part B の設計材料）— 手動キャンセル
依頼文は「手動キャンセル: カードは発動前の状態に戻る（現状どおり）」としていたが、**実測では戻らない**。対象選択（legacy `API.selectCard`）に `onCancel` が無く、`cancelChoiceV49` の継続（`engine/09_choice_request_v49.js` `dispatchChoiceContinuationV49`）は「`cb.onCancel` があれば呼ぶ」だけで、中止処理を呼ばない。
- 伏せたリビングデッドの呼び声（対象に取れるカードあり）で対象選択を開いて「やめる」: 選択は閉じ、チェーン無し、罠は**表のまま魔法・罠ゾーン**に残る（Journal に載るのは `CHOICE_CANCEL_V49` 1件）。発動ボタンも出ない（カードは失われる）。
- 手札の月の書で同様: **手札へ戻らず魔法・罠ゾーンに残る**。
- つまり「免疫で候補が0」と「手動キャンセル」は**同じ停止状態**に至る。テストは現行の挙動を固定している（`cancel pin TODAY (known defect…)`）。part B が単一の中止処理を入れたらこのピンは意図どおり変わる。**この点は依頼の前提と食い違うため、設計の最初に確認してほしい**。（セーブ→再開では S03-U35 の `recoverInterruptedActivationAfterLoadS03` が発動前へ戻す。ライブのキャンセルには適用されない。）

## コスト支払い済みの失敗 — 現行の挙動（part B の設計材料）
`prepareDuelActivation` の順序は 表にする（または手札から魔法・罠ゾーンへ MOVE）→ `cost` → `selectTargets`。`cost` が `done(false)` した時だけ `opts.onAbort` が走る（手札発動の魔法は手札へ戻る。伏せ罠は戻す処理が無く、表のまま）。**コストを払った後に対象選択が失敗した場合は何も戻らない**:
- コスト（LP・リリース・捨てる等）は払われたまま（Journal に載る＝Replay に含まれる）。返却されない。
- カードは魔法・罠ゾーンに表で残る（`onAbort` は呼ばれず、手札へも戻らない）。チェーン無し、選択待ち無し。プレイヤーに見えるのは「選択できるカードが足りません」だけ。
- 合成カード（condition は生のプール、cost で 1000LP、対象は保護された場）で固定: LP 8000→7000、カードは `sz/up`、手札0、`chain:0`、トースト `選択できるカードが足りません`、Journal は `MOVE`,`LP`。
- 対照（今も動く中止）: `cost` が払えない時は `opts.onAbort` で手札へ戻り、LP 不変、トースト `コストを払えません`。
- 実カードでの同形（計測、修正していない）: 洗脳－ブレインコントロール（800LP、オベリスクだけの場）、早すぎた埋葬（800LP、アーマー+墓地）、自律行動ユニット（1500LP、アーマー）、ゴッドバードアタック（リリースした鳥獣族が戻らない、複数対象のため未修正）。デュアルスパークも修正前は同形だった（本単位で condition+cost を直した）。
**今の挙動は既に誤り**（コスト喪失 + カード喪失）。依頼どおり「カードだけ戻してコストを黙って失わせる」修正はしていない。part B では、(1) 対象選択の前にコスト支払いを確定しない（選択を先にする）か、(2) コスト支払い済みの失敗を単一の中止処理で巻き戻す（Journal ごと）か、のどちらかの設計判断が必要。本単位は前者の形（`condition` で事前に断る）を、再現できた主要カードにだけ入れた。
