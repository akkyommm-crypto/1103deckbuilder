# S03-U498 報告：召喚そのものの無効の窓を入れた（**挙動の変更あり**）

S03-U497 で処理順を実測して確定した設計 `docs/S03_MISSED_TIMING_DESIGN.md` の **(D)** を実装した単位。
対象は `docs/S03_MISSED_TIMING_DESIGN.md` 5-a #1 に残していた「召喚そのものの無効」。

根拠は当時裁定 **`WIKI-2CF23AA42E79`（回答日 2011-08-25、掲載ページ《血の代償》）1 件だけ**で、
新しい裁定は引いていない（`docs/S03_MISSED_TIMING_RULINGS.md` の S03-U498 節に、入れた判断ごとの層を分けて書いた）。

> 「この効果による通常召喚に対し《神の宣告》や《キックバック》・《昇天の角笛》などの召喚を無効にする
>   カードを発動できますか？」
> →「チェーン１で行われているならば、発動可能です。
>    チェーン２以上で行われ、召喚の後に別の処理がある場合はタイミングを逃す事になり発動できません。」

## 1. 直した食い違い

S03-U497 の実測では、解決中に行われる召喚には窓が **1 つも開かなかった**。つまりチェーン1 では
**当時できる《神の宣告》《キックバック》《昇天の角笛》の発動を潰していた**（チェーン2 の結果が
当時裁定と一致していたのは、規則としてではなく窓が無いせいだった）。

| | S03-U497 まで | S03-U498 |
|---|---|---|
| チェーン1（召喚の後に別の処理が無い）| 窓が開かない（**誤り**）| **窓が開く**（当時裁定どおり発動できる）|
| チェーン2 以上（召喚の後に別の処理がある）| 窓が開かない | 窓が開かない（**変更なし**。当時裁定どおり逃す）|
| 召喚無効のカードが場に無い | 窓が開かない | 窓が開かない（**変更なし**。Action も 1 つも増えない）|

## 2. 設計から 1 点だけ変えた場所（実測して変えた）

S03-U497 は窓を開く場所を `processChainEndV30` と書いていた。実装してみて測った結果、そこでは
**採れない**ことが分かったので、**遅延イベントの排出（`processDrainEventsV27`）の先頭**へ移した。

- `processChainEndV30` で窓を開いて `PROC_V27_WAIT` で止めると、その関数の**残りが飛ぶ**。
  残りには `eventChainResumeV11`（誘発イベントから始まったチェーンの続き）と `CHAIN_AFTER_V2` があり、
  どちらも公開済みの経路である。窓の後に `CHAIN_END` をもう一度流す形も `endLinkResolutionS03` を
  二度通すので採らない。
- 排出の先頭は「召喚成功のイベントを出す直前」＝ 当時裁定の言う「召喚成功時の激流葬・奈落より前」。
  チェーン終了より後なので、S03-U497 が障害 2 として挙げた
  「`processDrainEventsV27` に `pendingSummon` の条件が無いので `onNormalSummon` が窓より先に出る」も
  ここで開くこと自体が答えになった。

## 3. 入れた形

| 要素 | 入れたもの |
|---|---|
| 対象の決め方 | **許可リスト**。呼び出し元が積んだ `onNormalSummon` に `summonNegWindowS03:true` の印が付いたものだけ。印の無い召喚は従来どおり（列挙の漏れは「何もしない」側に落ちる）|
| 印を付けた呼び出し元 | **《血の代償》1 件だけ**。当時裁定がこのカードについて答えているため |
| 判定 | (A) の処理番号。刻んだ番号（召喚した時点）と排出時点の番号が同じなら開く。`missedTimingDropS03` の **R4** と同じ比較 |
| 前検査 | 召喚無効（`sc.summonNegate`）のカードがどちらの場にも無ければ、Action を 1 つも残さずに帰る |
| 無効のとき | 積んである `onNormalSummon` を落とし、モンスターを `MOVE` で墓地へ送る。《キックバック》（S03-U277）は `FX_BOUNCE` で手札へ |
| 「破壊された時」 | **発動しない**。召喚は成立していないので破壊でも「フィールドから離れた時」でもない |
| 保存・Undo | `pendingSummon.resumeS03.resolvedS03`。窓が開いたままの保存は `restoreProcessorAfterLoadS296` に足した `DRAIN_EVENTS` の待ちで戻り、窓は既存の `reopenSummonWindowAfterLoadS03` が開き直す |

## 4. 公開対象の対応範囲と未対応範囲

### 対応した（公開できる）範囲

- 《血の代償》の「通常召喚扱い」の召喚に対する召喚無効の窓。チェーン1 では開き、チェーン2 以上で
  召喚の後に別の処理があれば開かない。無効にしたときの取り消し（墓地へ／《キックバック》は手札へ）。
- 窓を跨ぐ保存・再開・Undo・Replay（専用テストの I が別 VM で固定している）。
- 文書: 設計書 (D) の「S03-U498 で入れた形」・5-f・5-a #1 の書き直し・#1-g の追加・§6 の採らない案 5 件、
  裁定記録の S03-U498 節（入れた判断ごとの層）。

### 未対応範囲（**挙動は S03-U497 のまま**）

- **解決中の特殊召喚**には窓が開かない（5-a #1-d）。`sc.summonNegate` の `kinds` に効果による特殊召喚の
  種別が無く、足すとカードスクリプト（公開済み）を全件直すことになる。根拠も `R1103-ROACH-003`
  （**回答日なし**）しかない。
- **《デュアル・サモナー》の効果による通常召喚**には印を付けていない（5-a #1-g）。この召喚は解決中の
  選択の再開の中で行われ、相手のエンドフェイズという別の進行の上に乗っているので、《血の代償》と
  同じ順になるかを**実測していない**。
- 窓の中身の 2 点: **ターンプレイヤー自身が発動できない**（5-a #1-e、`R1103-WARNING-006`、回答日なし）、
  **1 召喚に 1 チェーンブロックの制限が無い**（5-a #1-f、`R1103-RAIOH-002`、回答日なし）。
- 案 (b) を採ったことによる**近似 2 点**（設計書 (D) に記録）: 召喚から窓までの間だけ永続効果が
  適用される。無効の取り除き（`MOVE`）が (A) の処理番号を進めるので、同じ組に残っていたリリースの
  イベントはその後「最後に行われた処理」ではなくなる。どちらも実経路で差は観測していないが**未確認**である。
- S03-U496 からの未対応はそのまま残っている。**タイミングを逃す判定は確認済み 44 枚 / 65 組に限られ、
  全カード・全タイミング規則が完成したわけではない**（5-a #0 の 225 組ほか）。
