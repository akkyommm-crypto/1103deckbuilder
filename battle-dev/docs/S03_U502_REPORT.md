# S03-U502 報告：召喚を無効にされたモンスターを「フィールドに出なかった」扱いにした（5-a #1-i の修正）

S03-U498 で入れた召喚無効の窓は案 (b)（召喚はそのまま行い、無効のときだけ取り除く）なので、
手札から出したモンスターが一瞬だけモンスターゾーンに居る。そのため取り除いたときに
`v9DetectLeaveField`（`engine/18`。**盤面の差分**で離脱を検出するルール処理）が `onLeaveField` を
積んでいた。S03-U500 がそれを実測して 5-a #1-i に記録し、S03-U501 が当時裁定を引き直した。
**この単位でその 1 件を直した。**

## 1. 根拠

| 裁定 | 回答日 | 内容 |
|---|---|---|
| `WIKI-9E991E9B14E9`（《Sin トゥルース・ドラゴン》）| **2010-04-21** | 「フィールド上で破壊された扱いではない」 |
| `WIKI-643A78AB3480`（《デストラクション・ジャマー》）| **2008-03-19** | 「『フィールド上のモンスターを破壊する』扱いではありません」 |
| `WIKI-933C52FB1EC1`（《E・HERO ワイルドマン》）| 回答日なし | 「モンスターはフィールドに出なかった」 |

召喚が成立していないモンスターは、場からの離脱に数えない。

## 2. 直し方

取り除きの **Action 自身が申告する**。`MOVE` に `summonNegatedS03:<uid>` を付け、
`v9DetectLeaveField` がその 1 枚だけを離脱から外す。

- `v9DetectLeaveField` は `applyAction` の中で呼ばれる（`engine/00`）。申告を Action に乗せたので、
  **Journal 再生でも同じ Action から同じ判断になる**（モジュール変数では再生時に再現できない）。
- **申告の無い Action は何も変わらない。** テスト D が negative control で固定している
  （申告なしの `MOVE` は離脱を積む／申告の uid が合わなければ積む）。
- 申告を付けるのは**手札から出した召喚の取り消し 1 箇所だけ**。反転召喚とデュアル再召喚
  （召喚の前から場に居る）の離脱は**本当の離脱**なので変えていない。

変更したファイル: `engine/18_leave_field_v9.js`（引数に Action を取り、1 行の除外）、
`engine/00_state_actions.js`（Action を渡す 1 行）、`engine/1ZZY_summon_negation_window_s03.js`（申告）。

## 3. 影響範囲

`onLeaveField` を見る `passive` は **57 件**（全スクリプト監査）。S03-U501 までは、召喚を無効にされた
モンスターの分でもこの 57 件が応答しうる状態だった。いまはその場面で呼ばれない。

## 4. 公開対象の対応範囲と未対応範囲

### 対応した範囲

- 解決中の通常召喚（《血の代償》《デュアル・サモナー》の手札の枝）を無効にしたとき、
  そのモンスターの `onLeaveField` を積まない。UI 起点の通常召喚と同じ形になった。
- 枝の違いを固定（反転召喚・デュアル再召喚は離脱を積む）。
- Save/Load（別 VM）と Replay 監査でも同じ判断になることを固定。

### 未対応範囲

- **5-a #1-j**（残っている方）: 手札から出した召喚を無効にされても、`onDestroy` / `onSendToGrave` が
  積まれない。当時裁定（`WIKI-EFB088FAC57A`、**回答日 2010-05-17**）では「破壊され墓地へ送られた時」の
  効果が発動できる。影響しうるのは**通常召喚できるモンスター 176 枚**。
  直すには「フィールドに出ないまま破壊されて墓地へ送られた」という 3 つ目の取り除き方が要る（設計書 (E)）。
- 解決中の**特殊召喚**（#1-d）、窓の中身の 2 点（#1-e / #1-f）。どちらも**回答日なし**の根拠のみ。
- **タイミングを逃す判定は確認済み 44 枚 / 65 組に限られ、全カード・全タイミング規則が完成したわけではない。**
