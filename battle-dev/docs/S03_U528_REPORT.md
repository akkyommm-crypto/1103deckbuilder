  → 解決時に手札を数え直す（《マインドクラッシュ》で測った）。
- `WIKI-78672B59DAAC`（10/08/16）捨てるのと装備するのは**同時** → 同じ処理の中で続けて行う。

## 2. 実経路で測ったこと

`tools/test_s03_u528_transform_sphere.js`（19 PASS）。Replay 監査は 8 場面。

- A1: 登録と 3 つの効果（装備・守備表示・特殊召喚）、自己強化の永続効果、ゾーン限定の印の登録。
- B1: 相手の表側守備表示《デーモンの召喚》を選択し、手札 1 枚を捨てて装備 → 攻撃力 100 → 2600。
- B2: 1 ターンに 1 度なので 2 回目は発動できず（装備は 1 体のみ）。
- C1: 《マインドクラッシュ》をチェーンされて解決時に手札が 0 枚になった場合、装備されず攻撃力も変わらない。
- C2: negative control。相手に表側守備表示のモンスターが居ない場合は発動できない。
- D1: エンドフェイズに装備したモンスターが相手フィールドへ**表側守備表示**で特殊召喚され、攻撃力が戻る。
- D2: 正規の方法で特殊召喚されていない《溶岩魔神ラヴァ・ゴーレム》は装備されたままにならず墓地へ送られる。
- E1: 直接攻撃した後、バトルフェイズ終了時に守備表示になる（`attacked` と `pos` を実測）。
- F1: 《月の書》をチェーンされて裏側になった場合も装備され、攻撃力はアップせず（100 のまま）、
  エンドフェイズには表側守備表示で特殊召喚される。
- G: 当時裁定の ID、報告書、`tools/check.py` への登録。

関連テストも通過: 装備関係（equip_cards / equip_v15 / u268 / u311 / u312 / u313 / u315 / u341 / u411 / u412 /
u417 / u469 / u525）と v46 系は全体ゲートで通過を確認。

## 3. 未対応・後続課題

1. `WIKI-5C12010DECA5`（09/12/29）特殊召喚する位置（ゾーン）を決めるのはこのカードのコントローラー
   → engine にゾーンの選択が無いので**未対応**（空いている先に置かれる）。
2. `WIKI-D5DC083B1E5A`（10/01/25）トークンを装備した場合は「トークンを特殊召喚したカードに記載された
   数値」分アップする → engine はトークン作成時の数値を持つので、記載が無いトークン
   （冥府の使者カイエントークン）では一致しない。トークンを装備する場面自体も**未測定**。
3. `WIKI-2561E30DBB57`（10/01/25）《死霊ゾーマ》を装備した場合は攻撃力 1800 アップ
   → 罠モンスターのモンスターとしてのデータ（`asMonsterDbS03`）はゾーン限定なので、装備カードになると
   失われ、攻撃力はアップしない。**未対応**（罠モンスターを装備カードにする経路を残す必要がある）。
4. `WIKI-995438DB1F1C`（10/08/16）《フェルグラントドラゴン》の「墓地から特殊召喚されていた場合のみ」は
   **未測定**（蘇生制限の判定は D2 で測った）。
5. `WIKI-2EF617C51571` の分類のうち、表示形式の変更は裁定では永続効果だが、この実装は engine の既存の
   同じ文言のカード（《ゴブリン突撃部隊》）と同じ強制の誘発効果にしている（チェーンブロックを作る差が残る）。
   engine 全体の扱いなので、このカード固有の問題ではない。
6. 「裏側表示のまま装備カードになる」状態そのものは engine で表現できない（ゾーンを移るとカードは
   表側になる）。攻撃力がアップしない事を印で表して測った（F1）。
7. S03-U517〜U527 から持ち越しの項目は各報告書のとおり。
