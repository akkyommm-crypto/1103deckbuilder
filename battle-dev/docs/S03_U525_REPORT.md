### 共通側に足した 2 つ（カード実装を妨げていた不足）

1. 装備イベントに装備カード自身の uid（`cardUid`、engine/1E）。
   `equipUid` は装備 1 つごとの番号（`eq.equipUid = eq.equipUid || (++gs.uidSeq)`）でカードの uid とは別物なので、
   装備が外れた後は `equipCardOfEventV15` でそのカードを引けず、「墓地へ送られた」かを読めなかった。
2. 装備カード自身が場を離れた時の `onEquipDetached`（engine/00 の `reset`）。
   これまでは「装備を外す操作」（`FX_UNEQUIP`）と「装備モンスターが場を離れた」経路（engine/1N）だけが
   出していて、装備カードが破壊・墓地送り・除外で場を離れた場合は何も出ていなかった。
   ゾーン限定の印（`equipTo` / `equipUid`）を落とす前に 1 回出し、装備モンスター側に残る `equippedBy` も掃除する。
3. 解決の通し番号（`gs.resolveSeqS03`、`CHAIN_RESOLVE_TOP` で 1 進める）。
   解決中のリンク（`RESOLVING_LINK_S03`）は Action の外の変数なので Replay では null になり、
   積んだイベントの中身が live と変わって digest が合わなかった。Action の中で進める番号にしたので
   Replay・保存・再開でも同じ値になる（実測で digest 一致）。

## 3. 未対応・後続課題

1. `WIKI-02EA6A6B7D43`（10/08/04）装備魔法の発動にチェーンして破壊された場合の「装備されていない扱い」は、
   その経路で装備イベントが一度も起きない事に頼っている（間接的な再現）。装備の記録自体を持つ作りには
   していないので、**未対応**として記録する。
2. `WIKI-D9DF855BA1F8`（10/08/04）《黒いペンダント》を自身の効果で送った場合「同時に発動する扱い」は、
   両方が同じ墓地送りで誘発する事までは測ったが、「2 つのチェーンブロックが同時に積まれる」事自体は
   測っていない（**未対応**。SEGOC の積み方の確認は後続課題）。
3. 《セブン・ソード・ウォリアー》のシンクロ素材指定（チューナー＋チューナー以外 1 体以上）は
   共通のシンクロ機構（S03-U516）のままで、この単位では触っていない。
4. S03-U517〜U524 から持ち越しの項目は各報告書のとおり。
