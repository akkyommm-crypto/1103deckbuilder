# S03-U503 報告：表側守備表示の通常召喚を入れた（5-a 項目 3）

設計書 5-a の項目 3 に「表側守備表示の通常召喚が未実装」として残っていた分。
**回答日のある裁定が根拠**で、その裁定を実経路で再現できるようになった。

## 1. 当時裁定

`WIKI-0B439F71B94A`（**回答日 2011-04-18**、掲載ページ《ゴブリンドバーグ》）

> Q: 《聖なる輝き》が存在するときに**表側守備表示で通常召喚**し、効果を発動しました。このとき、
>    このカードが守備表示になる処理は発生しますか？ また、この時に特殊召喚したモンスターが
>    《E・HERO エアーマン》の場合効果はタイミングを逃さず発動できますか？
> A: 《聖なる輝き》が存在するときに表側守備表示で通常召喚して効果を使用した場合、守備表示になる処理は
>    行われません。また、この場合《E・HERO エアーマン》の効果を発動することができます。(11/04/18)

これは S03-U493 が使った `WIKI-9FC5B41EDCF4`（**回答日 2011-04-17**）の**裏返し**である。
表側攻撃表示で通常召喚した《ゴブリンドバーグ》は守備表示になる処理が「召喚の後の別の処理」になるので
《E・HERO エアーマン》が**逃す**。《聖なる輝き》があるときは最初から守備表示なのでその処理が行われず、**逃さない**。

## 2. 直す前（実測）

《聖なる輝き》がある状態の「セット」は `SET_MONSTER`（表側守備表示に置くだけ）だった。

| 実測 | 直す前 | 直した後 |
|---|---|---|
| Action | `SET_MONSTER`（`faceUpSetS03`）| `NORMAL_SUMMON`（`pos:'def'`）|
| 盤面 | 表側守備表示 | 表側守備表示（同じ）|
| `summonedTurn` | 付かない | 付く |
| 召喚成功のイベント | **無し** | `onNormalSummon` |
| 召喚無効の窓 | **開かない** | 開く（kind `normal`）|
| 通常召喚の権利 | 使う | 使う（同じ）|

召喚成功のイベントも窓も無かったので、当時裁定の場面（召喚誘発が働くかどうか）を実経路で再現できなかった。

## 3. 直し方

1. `NORMAL_SUMMON` が表示形式の申告を受ける（`a.pos==='def'` のときだけ表側守備表示。
   申告が無ければ今までどおり攻撃表示なので、**既存の Journal はそのまま再生される**）。
2. 窓からの再開（`runSummonWindowResumeS03`、`engine/40`）も `resumeS03.pos` を渡す。
3. セットの 2 つの入口（`doSetMonster` / `finishSetMonster`、`engine/70`）を、`mustSetFaceUp()` が
   真のときだけ **表側守備表示の通常召喚**へ振り替える。普通のセットは今までどおり `SET_MONSTER` である。
   振り替えは `finishNormalSummon` の `pos` 引数では**なく**、専用のオプション（`faceUpDefS503`）で渡す。
   **理由（ゲートで分かった）**: `engine/60` の FREE モードの盤面には「通常召喚（守備）」ボタンがあり
   `doNormalSummon(i,'def')` を呼んでいる。`pos` をそのまま使うと、その**公開済みのボタンの挙動まで**
   変わってしまう。当時のルールでは通常召喚の表示形式は表側攻撃表示だけで、表側守備表示になるのは
   《聖なる輝き》がある状態の「セット」だけである。
   最初の実装では専用関数を作ったが、`tools/test_s03_u483_event_identity_closure.js` の監査が
   「engine/70 の直接 `emitEvent` 呼び出しが 3 → 4 に増えた」ことを全体ゲートで検出したので、
   関数を増やさず既存の `finishNormalSummon` にオプションを渡す形に直した。
4. 《ゴブリンドバーグ》側は**変更なし**。守備表示にする処理は既に
   `me.card.pos!=='def'` の条件付きなので、最初から守備表示なら行われない。

## 4. 実経路で再現できるようになった裁定

| 場面 | 刻み | 結果 |
|---|---|---|
| 《聖なる輝き》あり（表側守備表示で通常召喚）| `NORMAL_SUMMON` 0→1 / `FX_SPECIAL_SUMMON` 1→2 / `FX_SEARCH` 2→3 | 守備表示にする処理が**無い**。《E・HERO エアーマン》は**逃さない**（《オーシャン》が手札へ）|
| 《聖なる輝き》なし（表側攻撃表示で通常召喚）| `NORMAL_SUMMON` 0→1 / `FX_SPECIAL_SUMMON` 1→2 / `FX_SET_STATE` 2→3 | 守備表示にする処理が**入る**。《E・HERO エアーマン》は**逃す**（S03-U493 のまま）|

## 5. 公開対象の対応範囲と未対応範囲

### 対応した範囲

- 《聖なる輝き》がある状態の「セット」が表側守備表示の通常召喚になる（リリースを伴う場合も含む）。
- そのため召喚成功の誘発・相手の応答・召喚無効の窓がすべて働く。無効にされても通常召喚の権利は戻らない
  （`WIKI-2C8BE04F46E9`、回答日 2007-03-26）。
- 当時裁定 `WIKI-0B439F71B94A` の場面と、その裏返し（`WIKI-9FC5B41EDCF4`）を両方テストで固定。
- 窓を跨ぐ Save/Load（別 VM。表示形式の申告ごと戻る）と Replay 監査。

### 未対応範囲

- `WIKI-1120DC4371F9`（回答日 2010-07-05）の「裏側守備表示にする**処理**は行いません」（《フォース・リリース》
  等が既にある状態で裏側にしようとする場合）は別の経路で、この単位では触っていない。
- 召喚無効まわりの未対応はそのまま（5-a #1-d / #1-e / #1-f / #1-j）。
- **タイミングを逃す判定は確認済み 44 枚 / 65 組に限られ、全カード・全タイミング規則が完成したわけではない。**
