### 2-2. 実経路での再現（修正前）

`WIKI-9FC5B41EDCF4` の盤面をそのまま組んだ。《ゴブリンドバーグ》を通常召喚 → その誘発で手札から
《E・HERO エアーマン》（攻 1800）を特殊召喚 → 続けてゴブリンドバーグ自身が守備表示になる。
相手は《奈落の落とし穴》を伏せている。最上位 Action ごとの番号（修正前）:

```
NORMAL_SUMMON      0 -> 1
COLLECT onNormalSummon  stamp=1 now=1 [ゴブリンドバーグ]
FX_SPECIAL_SUMMON  1 -> 2
FX_SET_STATE       2 -> 2   pos=def      ← 守備表示になる処理。番号が進まない
COLLECT onSpecialSummon stamp=2 now=2 [E・HERO エアーマン, 奈落の落とし穴]
FX_DESTROY_BANISH  2 -> 3                ← 《奈落の落とし穴》が解決し、エアーマンが除外された
```

**当時裁定では両方ともタイミングを逃す**のに、どちらも発動できていた。原因は 2 つ。

1. `FX_SET_STATE` の許可リストの条件が `a.face==='down' || a.flipSummon===true` で、**表示形式だけ・レベルだけの
   変更は型ごと数えられていなかった**（セットされたカードを発動する時の表返しを除くための条件が広すぎた）。
2. 「何か起きたか」の印が、盤面の署名（**各ゾーンの枚数とライフだけ**）・遅延イベント・**`logIt` の有無**の 3 つで、
   表示形式・攻守・レベル・カウンターの変化は**ログでしか判別できなかった**。

同じ形を 4 種類すべて実経路で測った（チェーン1 に測定対象、チェーン2 に《血の代償》の通常召喚）。

| 変わるもの | チェーン1 のカード | Action | 修正前 | 修正後 |
|---|---|---|---|---|
| レベル | 《トラゴエディア》④ | `FX_SET_STATE {lvDelta}` | 2 → 2（**数え落ち**。《奈落の落とし穴》が発動してしまう）| 2 → 3（逃す）|
| 表示形式（表側にする）| 《生命力吸収魔術》 | `FX_SET_STATE {face:'up'}` | 数え落ち | 逃す |
| 表示形式（守備にする）| 《ゴブリンドバーグ》の誘発 | `FX_SET_STATE {pos:'def'}` | 数え落ち | 逃す |
| 攻守 | 《突進》 | `MOD_ADD` | **ログだけが印**だった | 署名で判定 |
| カウンター | 《侵食細胞「A」》 | `COUNTER_ADD` | **ログだけが印**だった | 署名で判定 |

### 2-3. ログを印にできない理由（こちらも実測）

S03-U492 は「断りをログに書いて何もせず終わる許可リストの Action」10 種を除外していたが、この除外は
engine のソースを「できません／ありません／一杯です／埋まっています／空です／足りません」という語で
機械監査して作っていたため、**`COUNTER_ADD` の「これ以上◯◯カウンターを置けない」を拾えていなかった**。
`COUNTER_REMOVE` の 0 個の取り除き（「0つ取り除いた（残0）」）も同じ。
どちらも空振りなのにログが 1 行増えるので、**空振りを処理と数えて誤って逃させる**側の誤りである。

逆向きの弱さ（ログを書かない処理は数え落ちる）と合わせて、ログを印にする設計自体を外した。

### 2-4. 修正の内容（共通処理のみ）

- **盤面の署名を作り直した**（`missedTimingSigS03` / `missedTimingCardSigS03`）。
  ライフと各ゾーンの枚数に加えて、モンスターゾーン・魔法罠ゾーン・フィールドゾーンの**カード 1 枚ごとの状態**を混ぜる:
  `uid` / 表裏 / 表示形式 / `lvMod` / `mods`・`statModsV14`・`lvModsV16`・`charV17` の件数 / `xyz` の数 /
  `equipTo`・`equippedBy` / `negated`・`negV13` / `dualUp` / `counters`（種類と数）。14 欄をテストで 1 つずつ実測している。
- **どの Action でも走る帳簿の欄は入れない**（`procedureBaseStats`、攻撃済みフラグ、表示形式を変えた記録）。
  入れると空振りの Action まで「起きた」と判定して**誤って逃させる**。これもテストで実測している。
- **ログの印を外した**。`engine/00` の `logIt` は S03-U491 以前の 1 行に戻した。
- **`FX_SET_STATE` の条件を反転した**。「セットされたカードを発動する時の表返し」だけを除く
  （`face:'up'` かつ `pos` 無しかつ `reason:'発動'`）。この形を出すのは engine の **3 箇所だけ**で、
  カードスクリプトには 1 件も無いことをテストで固定している。効果で表側にする場合（`v10FlipEffect`、
  ダメージ計算前のリバース）は数える。
- **`clear` を除いた**。`STAT_MOD_V14` / `LEVEL_MOD_V16` / `CHAR_MOD_V17` の修整の解除は掃除なので数えない
  （`MOD_CLEAR` / `COUNTER_CLEAR` が許可リストに無いのと同じ扱い）。

修正後、`WIKI-9FC5B41EDCF4` の盤面では `FX_SET_STATE {pos:'def'}` が 2 → 3 と進み、エアーマンの召喚誘発と
相手の《奈落の落とし穴》の**両方がタイミングを逃し**、エアーマンは除外されず場に残る。

## 3. 条件(2) ─ 候補の全件監査

`collectHandlers` が召喚成功のイベント（`onNormalSummon` / `onSpecialSummon` / `onFlip`）で拾い得る
カードスクリプトを**全件**列挙した。**518 件**。エンジン自身の関数で分類した内訳:

| 区分 | 件数 | 扱い | 根拠 |
|---|---|---|---|
| 強制誘発 | **255** | 逃さない | R1。`sc.forced` / `forcedForEventS03` / v4 effect の `forced` |
| 「時」と読める任意誘発 | **218** | **逃す** | R2 / R3 / R7 |
| 「場合」と読める任意誘発 | **15** | 逃さない | R7 |
| 召喚無効のカード | **6** | 逃さない（別タイミング）| `WIKI-2CF23AA42E79`（11/08/25）|
| 文言が読み取れない | **24** | 逃さない（現状維持）| 旧「リバース:」表記など |

S03-U492 は「配線だけで決める（テキストは使わない）」としていたが、この監査で**配線だけの判定も誤る**ことが分かった。

- **「場合」15 件**（《魔導戦士 ブレイカー》《ハンニバル・ネクロマンサー》《D－HERO ディスクガイ》
  《E・HERO ガイア》《茫漠の死者》《光神機－轟龍》《電磁ミノ虫》《夜霧のスナイパー》《名工 虎鉄》
  《赤い忍者》《青い忍者》《ハネハネ》《ダッカー》《デスグレムリン》《デスハムスター》）と
  **文言が読み取れない 24 件**、計 **39 件を誤って落としていた**（FREE モードでは召喚無効の 6 件も）。
- 逆に、旧「リバース:」表記ではなく「このカードが**反転召喚に成功した時**」と書かれた 4 枚
  （《スカラベの大群》《メデューサ・ワーム》《ガーディアン・スタチュー》《イナゴの軍勢》）は
  `onFlip` でしか拾われないため、**配線だけでも文言だけでも分けられない**。反転召喚も召喚として扱う。

そこで種別は「**配線と文言の両方**を満たすものだけ」に変えた（`missedTimingTextKindS03`）。
「〜に成功した時／された時／した時」＝ `'toki'`、「〜した場合」＝ `'baai'`、1 枚に混在すれば `'baai'`（曖昧なので落とさない）。
文言が読み取れないものも落とさない。種別は 2 つに分けた。

- `summonSuccess` — 召喚句が「時」の発動（上の 4 枚を含む）
- `flipSummonReverse` — 反転召喚で条件が満たされた「リバースした時」の発動

**個別例外（R5）の宣言は 0 件**のままである。当時裁定 123 件と候補 518 件を照合し、R5 の 3 枚
（《ダーク・スプロケッター》08/04/19・《ファラオの化身》09/05/15・《アーケイン・ファイロ》08/11/21）が
いずれも**墓地送りを条件とする誘発**で召喚成功の候補に入っていないことを確認した（テスト D7 で固定）。
召喚成功を条件とする発動の個別例外は、この範囲では見つかっていない。

実経路の対照（テスト E）: チェーン1 =《成金ゴブリン》（ドロー＋LP）、チェーン2 =《血の代償》の通常召喚。

| 召喚するモンスター | 文言 | 結果 |
|---|---|---|
| 《魔導戦士 ブレイカー》 | 場合 | **逃さず**魔力カウンターを 1 つ置く。相手の《奈落の落とし穴》（時）だけが逃す |
| 《E・HERO エアーマン》 | 時 | 自身の召喚誘発も相手の応答も逃す |

## 5. 未対応（**全体は完成していない**）

設計書 5-a に表として入れた。要点だけ:

1. **召喚そのものの無効**（`SUMMON_WINDOW_*` / `summonNegatorsV2` / `beginSummonWindowV2`）。
   `WIKI-2CF23AA42E79`（回答日 2011-08-25）。**同じ番号判定を入れれば正しい、とは決めていない** —
   召喚成功**より前**の処理順と当時裁定を確認してから設計する。
2. **効果で表側にされたリバース効果**（《皆既日蝕の書》《生命力吸収魔術》の経路）。
   `flipSummonReverse` は反転召喚（`evt.flipSummon`）だけを見ている。
3. **表側守備表示の通常召喚が未実装**。`mustSetFaceUp` は「セットする場合」だけなので、
   《聖なる輝き》がある状態での表側守備表示の通常召喚ができず、`WIKI-0B439F71B94A` の裏返しを
   実経路で再現できない（テスト G2 で、`doNormalSummon(0,'def')` が攻撃表示になることを実測して固定）。
4. **破壊・墓地送りが条件の誘発**の種別（`WIKI-378544C74049`《砂塵の大竜巻》08/05/30 ほか）。
5. 署名に入れていない状態しか変えない処理（ライフも破壊も動かない `ATTACK`、`charV17` を同じ件数で入れ替える処理）。
   いずれも「逃さない」＝安全な側に落ちる。
6. タイミングを逃したことを**プレイヤーに伝える UI** が無い。
7. `WIKI-CF642F23F1C8`《カオスポッド》11/08/03 は当時「調整中」（`RULING_UNRESOLVED`）。
8. スクリプトの強制／任意が現行テキストと食い違うカード（《魔導戦士 ブレイカー》《ハンニバル・ネクロマンサー》は
   「場合に発動する」＝強制だが `forced` を宣言していない）。いまはどちらでも落とさないので対局は変わらない。
9. `FX_OVERLAY` の reducer は、トークンを素材にしようとした場合に **`removeFrom` でゾーンから取り出した後で**
   「トークンはエクシーズ素材にできません」とログを書いて終わる（`engine/00` の `case "FX_OVERLAY"`）。
   トークンは場を離れれば消えるので結果が間違いとは言い切れないが、素材にならないのに取り出している。
   本単位では触っていない（番号の数え方には影響しない）。読んで気づいただけで、対局での再現は取っていない。

統合・公開は GitHub Actions の `verify-battle` がその SHA で成功したことを確認してからになる。
