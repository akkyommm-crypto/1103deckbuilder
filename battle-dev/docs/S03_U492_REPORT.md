ユーザー指示の 4 条件に沿って、S03-U491 の機構を直し、第 1 種別を有効にした。
設計は `docs/S03_MISSED_TIMING_DESIGN.md`（1-a / 3(A) / 3(B) / 3(C) / 6）、試験は

## 1. 条件① 召喚成功後の応答と、召喚そのものの無効を分離した

`cards` 欄はどちらも「血の代償」だが、これは裁定が載っている Wiki ページの名前で、発動するカードではない。

| 裁定 ID | 問われているカード | タイミング | 回答日 | 取得日 |
|---|---|---|---|---|
| `WIKI-2B88D7C8D921` | **《落とし穴》** | **召喚成功後の応答** | **なし**（本文に日付が無い） | 2011-08-26 |
| `WIKI-2CF23AA42E79` | **《神の宣告》《キックバック》《昇天の角笛》** | **召喚そのものの無効** | **2011-08-25** | 2011-08-26 |

答えはどちらも「チェーン１で行われているならば、発動可能です。 チェーン２以上で行われ、召喚の後に別の処理が
ある場合はタイミングを逃す事になり発動できません。」で、末尾の「(11/08/25)」は後者だけが持つ。

**訂正したもの**（誤記は「以前こう書いた」という訂正の記述としてだけ残した）:

  片方の回答日を両方に付けていた記述を直し、2 件を別タイミングとして分けた
- `tools/test_s03_u487_blood_offering_normal_summon.js` の冒頭の引用
- `docs/S03_U487_REPORT.md` の裁定の節（**S03-U492 で訂正**の囲みを追加）

- `docs/S03_MISSED_TIMING_RULINGS.md` の冒頭（`cards` 欄の意味と `answerDate=None` の意味）

**本単位の対象は召喚成功後の応答だけ**で、召喚無効（`SUMMON_WINDOW_*` / `summonNegatorsV2` /
`beginSummonWindowV2`）には一切触っていない。試験 B と I がそれを固定している

無効にもできない」という別の仕様判断になるので、裁定と実装の対応だけ記録して S03-U493 以降に回した。

また、この 2 件で逃すのは**応答する側のカード**（《落とし穴》等）であって《血の代償》ではない。
《血の代償》は宣言表にも種別にも入れていない（試験 B の最後の判定）。

## 2. 条件② POINT 窓は消さず、召喚成功を条件とする発動だけを落とす

判定は `collectHandlers`（`engine/40`）の戻り値 1 箇所だけで行う。種別 `summonSuccess` は
**カードのテキストではなくエンジンの配線**で決まる — `collectHandlers` が
`onNormalSummon` / `onSpecialSummon` / `onFlip`（`evt.flipSummon` が真のときだけ）で拾った候補が、
「召喚成功を条件に発動している」ことの構造的な証拠になる。これで次の 2 つが同じ 1 つの規則で扱える。

- 召喚されたモンスター自身の召喚誘発（《E・HERO エアーマン》等）
- 相手の召喚に反応する罠（`onOtherSummon`。《落とし穴》《奈落の落とし穴》《激流葬》等）

**通常の優先権・応答機会は触っていない。** 召喚成功後の POINT 窓（`summonFast`）はそのまま開き、
一般のクイックエフェクトは今までどおり発動できる。実測（試験 D）でも、チェーン2の召喚で
《奈落の落とし穴》側が落ちた後も POINT 窓には《血の代償》が応答候補として出ていた。
《奈落の落とし穴》はもともと POINT 窓の候補ではなく、経路は `collectHandlers` だけである
（これも試験 D で固定した）。

## 3. 条件③ Action 番号の数え方を作り直した

### 拒否リストは向きが逆だった

S03-U491 は「帳簿の Action を 39 種列挙して除外し、それ以外では番号を進める」拒否リストで、
設計書は「取りこぼしても『逃さない』＝現状維持側に倒れるので安全」と書いていた。**これは逆**である。
除外リストの漏れは**番号を進めてしまう**ので、刻みと現在値が食い違い、**誤って逃させる**側に落ちる。

実測でその欠陥が出た。《血の代償》がチェーン１で通常召喚した場合（`WIKI-2B88D7C8D921`:
**《落とし穴》を発動できる**）でも、召喚と遅延イベントの取り出しの間に `SPECIAL_WIN_DEFER_S03`
（勝敗の確認）が 1 回走り、番号が **3 → 4** とずれていた。S03-U491 では宣言が 0 件だったので
対局には出ていなかったが、宣言を入れればその瞬間に正しい発動を潰していた。
試験 H5 が、この性質を足し直すとチェーン１で《奈落の落とし穴》が発動できなくなることを実測で再現している。

### 許可リスト＋「本当に何かが起きた」判定

`applyAction` の最上位の適用で、次が揃ったときだけ 1 進める。

1. Action の種類が許可リスト `MISSED_TIMING_PROCESSING_S03` にある（**表に無いものは進めない＝逃さない**）
2. 適用が例外で終わっていない
3. 本当に何かが起きた — 盤面の署名（各ゾーンの枚数とライフ）が変わった／条件が満たされた遅延イベントが
   積まれた／`logIt` が書かれた（下の除外あり）

**ログを印にできない Action**: 許可リストの一部の reducer は「適用できなかった理由」をログに書いて
何もせずに終わる（`モンスターゾーンが一杯です`、`このターンは既に通常召喚しています` 等）。
ログだけを印にすると空振りを処理と数えてしまうので、この 10 種（`NORMAL_SUMMON` / `SET_MONSTER` /
`SET_ST` / `TOKEN_CREATE` / `FX_SPECIAL_SUMMON` / `FX_EX_SUMMON` / `FX_RITUAL_SUMMON` / `FX_OVERLAY` /
`FX_DETACH` / `FX_MONSTER_EQUIP_V46`）は署名の変化だけで判定する。
**この一覧は試験 A が engine のソースから機械的に監査して一致を固定している**ので、
他の許可リストの Action に断りのログが足されればテストが落ちる。

### 実測（条件③の確認項目）

| 確認項目 | 結果 |
|---|---|
| 帳簿の Action（`EVENT_QUEUE_V31` / `SET_PRIORITY` / `SPECIAL_WIN_DEFER_S03`） | 進めない |
| 空振りの処理 Action 9 種（対象が無い `FX_TO_GRAVE` / `FX_BANISH` / `FX_BOUNCE` / `FX_SELF_TO_GRAVE` / `SET_ST` / `SET_MONSTER` / `MOVE` / `TOGGLE_POS` / `FLIP`） | 進めない |
| 断りをログに書いて終わる Action（通常召喚権を使い切った状態の `SET_MONSTER`） | 進めない |
| 適用が例外で終わった場合 | 進めない |
| 《激流葬》の同時破壊（`FX_WIPE_ZONE` ×2、2 つめは空振り） | 3 件の `onLeaveField` が同じ番号 |
| 戦闘の相打ち（`BATTLE_CLEANUP` 1 回） | 2 件の `onLeaveField` が同じ番号 |
| 同一解決中の複数特殊召喚 | `flushResolutionSummonBatchV2` が 1 イベントにまとめるので刻みも 1 つ |

イベントも積まず、ログも書かない処理（表示形式の変更だけ、攻守やレベルの増減だけ、
カウンターの増減だけ）。設計書の 3(A) に明記した。

### 既存テストへの影響

`tools/test_s03_u491_missed_timing_mechanism.js` の 3 件の判定文を書き直した（**40 PASS は変わらない**）。
S03-U491 の (A) を作り直したので、拒否リストを固定していた判定（A ブロックの 2 件）と、
`missedTimingModeS03` の既定値・刻みの実装を固定していた判定（B / C の 1 件ずつ）が設計と合わなくなったもの。
**期待値を緩めたのではなく、新しい設計（許可リスト・種別）を同じ強さで固定し直した**:

- 「除外表に帳簿の Action が入っている」→「**許可表に盤面を変える Action が入っている**」＋
  「帳簿・提示・進行・掃除の Action は許可表に**無い**（表に無いものは進めない＝逃さない）」（13 種で確認）
- 「`missedTimingModeS03` の既定値は `never`」→「**宣言も種別も無い発動は判定しない**」
  （`missedTimingClassS03` が `null` であることも併せて確認）
- 刻みの実装のソース固定を新しい式に合わせた

その他の召喚関連テストは期待値の変更なしで通る: U487 32/0、U488 21/0、U489 19/0、U486 25/0。
