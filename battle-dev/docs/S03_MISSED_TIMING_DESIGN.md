# 「タイミングを逃す」の設計（共通エンジン課題）

S03-U487 / U488 / U489 が未解決として残した「チェーン2以上で召喚し、その後に別の処理がある場合はタイミングを逃す」を、
カード個別の対処ではなく共通処理として入れるための設計。
**S03-U491 で機構（A)(B)(C) を入れ（宣言 0 件なので挙動は変わらなかった）、S03-U492 で (A) を作り直して
「召喚成功を条件とする発動」1 種別を有効にした。S03-U493 で (A) の数え落ちを直して候補 518 件を全件監査し、
S03-U494 でその文言分類の時代混在を当時裁定と照合した。** 他の種別・カードは S03-U497 以降で段階的に行う。
**召喚そのものの無効（`SUMMON_WINDOW_*`）には広げていない**（5-a #1）。

**S03-U496 で公開できる範囲を確定した。** (B-2)(B-3) の「文言＋配線」で決まる候補のうち、
当時の根拠で**任意性・発動条件・例外**を確認できた（カード, イベント, 効果）だけを落とす
**許可リスト (B-5)** を入れた。落とす組は実測で **290 → 65**（44 枚）になった。
許可リストに無いものは落とさない ＝ S03-U491 以前の挙動を維持する。
これは**未対応**であって「逃さないという裁定が確定した」のではない（5-a）。

### 1-b. 「血の代償自身が逃す」ではない

この 2 件で逃すのは**応答する側のカード**（《落とし穴》等）であって、《血の代償》ではない。
《血の代償》の効果は誘発効果ではなく、チェーンブロックを作って通常召喚を行う起動相当の効果なので、
宣言表にも種別にも入らない。

## 3. 設計

### (A) 処理番号 `procStepS03` — S03-U492 で作り直した

`gameState.procStepS03` は「**行われた処理**」の通し番号。`applyAction` の最上位の適用で、次の 3 つが
揃ったときだけ 1 進める（`engine/1ZZX` の `missedTimingBeginS03` / `missedTimingEndS03`、`engine/00:216`）。

1. その Action の種類が**許可リスト** `MISSED_TIMING_PROCESSING_S03` にある
   （値が関数の型はその Action に対して真を返したときだけ。`FX_SET_STATE` は「セットされたカードを
   発動する時の表返し」＝ `reason:'発動'` の形だけを除く。`STAT_MOD_V14` / `LEVEL_MOD_V16` /
   `CHAR_MOD_V17` は付けるときだけで、`clear`（修整の解除）は掃除なので数えない）
2. 適用が**例外で終わっていない**
3. その適用の中で**本当に何かが起きた** — 次のどちらか。
   - **盤面の署名**が変わった
   - 条件が満たされた**遅延イベントが積まれた**
   署名も呼び出し回数も 1 回の `applyAction` の前後でしか比べないので状態に入れず、保存・digest にも出ない。

**盤面の署名（S03-U493 で作り直した）**: ライフと各ゾーンの枚数に加えて、モンスターゾーン・魔法罠ゾーン・
フィールドゾーンの**カード 1 枚ごとの状態**を混ぜる — `uid` / 表裏 / 表示形式 / `lvMod` /
`mods`・`statModsV14`・`lvModsV16`・`charV17` の件数 / `xyz`（素材）の数 / `equipTo`・`equippedBy` /
`negated`・`negV13` / `dualUp` / `counters`（種類と数）。
**どの Action でも走る帳簿の欄は入れない**（`procedureBaseStats` の整理、攻撃済みフラグ、
表示形式を変えた記録、継続効果の再計算）。入れると空振りの Action まで「起きた」と判定して誤って逃させる。

**ログは印にしない（S03-U493 で外した）**: S03-U492 は 3 番目の印として `logIt` の有無を見ており、
許可リストのうち「断りをログに書いて何もせずに終わる」10 種だけを除外していた。これは二重に弱い。

- 除外の列挙が漏れると**空振りを処理と数えて誤って逃させる**。実際に漏れていた:
  カウンターの `COUNTER_ADD` は上限に達すると「これ以上…置けない」と書いて何もせず終わるが、
  S03-U492 の機械監査は「できません／ありません／一杯です…」という語でログ行を探していたため
  「置けない」を拾えず、除外にも入っていなかった。`COUNTER_REMOVE` の 0 個の取り除きも同じ。
- 逆に、**ログを書かない処理は数え落ちる**。

署名を 1 枚ごとの状態まで広げたので、許可リストの Action が成功したときは署名か遅延イベントの
どちらかが必ず動く。`logIt` 側の呼び出しも消した（`engine/00` の `logIt` は元の 1 行に戻した）。

#### S03-U493 で再現した数え落ち（実経路）

#### S03-U491 の拒否リストが誤りだった理由（実測）

S03-U491 は逆向きで、「帳簿の Action を 39 種列挙して除外し、それ以外では進める」拒否リストだった。
当時の設計書は「取りこぼしても『逃さない』＝現状維持側に倒れるので安全」と書いていたが、**これは逆**である。
除外リストの漏れは**番号を進めてしまう**ので、刻んだ値と現在値が食い違い、**誤って逃させる**側に落ちる。

S03-U492 の実測でその欠陥が実際に出た。《血の代償》がチェーン１で通常召喚した場合
（`WIKI-2B88D7C8D921`: **《落とし穴》を発動できる**）でも、召喚と遅延イベントの取り出しの間に
`SPECIAL_WIN_DEFER_S03`（勝敗の確認）が 1 回走り、番号が **3 → 4** とずれていた。
S03-U491 で宣言が 0 件だったため対局には出ていなかったが、宣言を入れればその瞬間に正しい発動を潰していた。

許可リストなら**表に無い Action は番号を進めない ＝ 逃さない ＝ 現状維持**なので、漏れは安全な側に落ちる。
その代わり許可リストは不完全であり、**実際には「別の処理」なのに数えていない Action があり得る**。
その場合は「逃すべきものを逃さない」＝ S03-U491 以前の挙動になる。これは意図した倒し方で、
対局が壊れない側である。表は宣言を増やすたびに実測で足していく。

**(B-5) 公開範囲の許可リスト（S03-U496）**: (B-2)(B-3) は「現行テキストの文言 ＋ 配線」で落とす候補を
決めていた。S03-U494 / U495 の照合で、その **290 組のうち当時の根拠で裏付けられているのは一部だけ**だと
分かった（3(B-4)）。S03-U496 で、**当時の根拠から該当効果の次の 3 つを確認できた（カード, イベント, 効果）
だけ**を落とすようにした。

1. **任意性** — 当時裁定が「発動しない事は可能」と答えている、または当時テキストのその文が「できる」と書いている
2. **発動条件** — 「〜に成功した時」であること（当時裁定の引用、または当時テキスト）
3. **例外が無いこと** — 強制でない（R1）、召喚無効でない、当時裁定が**調整中**でない（R6）、
   R5 / R10 の宣言が無い、リバース効果ではない（R8）

**許可リストに無いものは落とさない。** これは S03-U491 以前の挙動を維持する判断であり、
**「逃さないという裁定が確定した」のではない**。未対応である（5-a）。

根拠の取り方は 2 通り。

| 根拠 | 条件 | 枚数 |

#### 効果単位で管理する（条件3）

1 つのイベントに複数の効果が配線されているカードでは、**イベント別の文言抽出だけでは効果別の判定にならない**。
実測では該当は 1 枚だけで、**《アルカナフォースIII－THE EMPRESS》の `onNormalSummon` に
`coin`（強制）/ `heads-summon`（任意）/ `tails-discard`（強制）の 3 効果**が配線されている。
この 1 枚は許可リストに入れていない。許可リストは `keys` でイベントごとの効果キーを指定できるようにしてあり、
**`keys` が無いまま複数効果のイベントに当たった場合は落とさない**（`missedTimingConfirmedS03`）。
候補がどの効果かは `ctx.v4EffectKey`（`collectHandlers` の条件判定で決まる）から取り、決められなければ
落とさない側に倒す。

**召喚無効は入らない**: `sc.summonNegate`（《神の宣告》《神の警告》《重力崩壊》《キックバック》
《エレキャンセル》《ライト・バニッシュ》の 6 枚）は召喚成功より**前**の別タイミング
（`WIKI-2CF23AA42E79`、回答日 2011-08-25）なので、`missedTimingDropS03` で明示的に外す。

宣言と種別の関係: `never` の宣言は種別より強い（R5）。強制誘発は種別に当てはまっても落とさない（R1）。
`miss` の宣言はイベントを問わず逃す。宣言も種別も無い発動は**判定しない**（＝現状維持）。

### (D) 召喚無効の窓（S03-U497 で確定した設計。**S03-U498 で実装した**）

### (E) 召喚を無効にされたモンスターの行き先（S03-U501 で実測。**挙動は変えていない**）

S03-U498〜U500 で入れた取り消しの形を、裁定 DB を**召喚無効の側から**引き直して照合した。
当時裁定の本文は `docs/S03_MISSED_TIMING_RULINGS.md` の S03-U501 節。

**当時の形（回答日のある 4 件から読み取れるもの）**:
**破壊されて墓地へ送られるが、フィールドで破壊されたのではない。**

- 「破壊され墓地へ送られた時」を条件とする効果は**発動する**（`WIKI-EFB088FAC57A`、回答日 2010-05-17）。
- 「フィールド上のモンスターを破壊する」扱いでは**ない**（`WIKI-643A78AB3480`、回答日 2008-03-19）。
  「フィールド上で破壊された」扱いでも**ない**（`WIKI-9E991E9B14E9`、回答日 2010-04-21）。
- 通常召喚の**権利は戻らない**（`WIKI-2C8BE04F46E9` / `WIKI-2ABC596B02C7`、回答日 2007-03-26）。
- 反転召喚を無効にされた場合は「リバースしなかった」扱い（`WIKI-43E80F61C77D`、回答日なし）。

**いまの 5 つの取り消し経路（S03-U501 で実測）**:

| 経路 | 取り消しの Action | そのモンスターに積まれるイベント | `graveInfo` |
|---|---|---|---|
| UI 起点の通常召喚（手札から）| `MOVE` | **無し** | 無し |
| UI 起点の特殊召喚手順（手札から）| `MOVE` | **無し** | 無し |
| UI 起点の反転召喚（場のカード）| `FX_TO_GRAVE byDestroy` | `onDestroy` / `onSendToGrave` / `onRemove` / `onLeaveField` | `byDestroy` 真 |
| 解決中の通常召喚（S03-U498）| `MOVE` | `onLeaveField` **だけ** | 無し |
| 解決中のデュアル再召喚（S03-U500）| `FX_TO_GRAVE byDestroy` | `onDestroy` / `onSendToGrave` / `onRemove` / `onLeaveField` | `byDestroy` 真 |

**食い違い**（5-a #1-j）:

1. **手札から出した召喚を無効にすると、そのモンスターのイベントが 1 つも積まれない。**
   当時裁定（回答日 2010-05-17）では「破壊され墓地へ送られた時」の効果が発動できる。
   影響しうるのは**通常召喚できるモンスター 176 枚**（自分の破壊／墓地送りを見る `passive` を持つもの。
   S03-U501 で全件数えた）。
2. 解決中の通常召喚では、逆に**場からの離脱だけ**が積まれる（5-a #1-i）。
   当時裁定では「モンスターはフィールドに出なかった」扱いなので、これは出てはいけない方である。

**合っているところ**: 通常召喚の権利（回答日 2007-03-26）と、反転召喚を無効にしたときにリバース効果が
出ないこと（回答日なし）は、いまの実装でも当時裁定どおりである（S03-U501 のテスト D で固定した）。

**直すときに要る形**（次の単位への設計）:
「**フィールドに出ないまま破壊されて墓地へ送られた**」という取り除き方が engine に無い。
いまある道具は `MOVE`（何も起きない）と `FX_TO_GRAVE byDestroy`（フィールドでの破壊として全部起きる）の
2 つだけで、その中間が無い。入れるなら
`onDestroy` / `onSendToGrave` は積み、`onLeaveField` は積まず、「フィールドで破壊された」ことを条件とする
判定（`graveInfo.from==='mz'`、「Sin」の蘇生条件、《デストラクション・ジャマー》）には当たらない、
という 3 つ目の取り除き方になる。`v9DetectLeaveField`（`engine/18`）は盤面の差分で離脱を検出するので、
そこに「召喚無効で消えた分は離脱に数えない」という除外を入れる必要がある。
**公開済みのルール処理**に触るので、測ってから別単位で行う。

### (C) 判定は `collectHandlers` の 1 箇所

誘発候補を 1 件落とす条件（`missedTimingDropS03`）:

1. その誘発の元イベントに `stepS03` が刻まれている（刻みの無い `emitEvent` 直接呼び出しと古い保存は判定しない）
2. 刻まれた `stepS03` が、いま提示しようとしている時点の `gameState.procStepS03` と**異なる**（R2 / R4）
3. そのカードが `never` と宣言されて**いない**（R5）
4. そのカードが `miss` と宣言されている、**または**種別に当てはまる（B-2）
5. その候補が**強制ではない**（`triggerCandidateForcedS03(c) === false`、R1）

**通常の優先権・応答機会には触らない。** 召喚成功後の POINT 窓（`summonFast` / `flipFast`、
`pointResponsesV27` → `getChainResponsesV2`）はそのまま開き、一般のクイックエフェクトは
チェーン終了後に今までどおり発動できる。実測でも、チェーン2の召喚で《落とし穴》側が落ちた後も
POINT 窓には《血の代償》（クイックエフェクト）が出ていた。

落とした候補は診断用の `MISSED_TIMING_DROPS_S03` に残す（digest にも保存にも入れない）。
落とした結果候補が 0 件になれば、`emitEvent` は `false` を返して従来どおり次へ進む。

## 4. 保存・再開・Replay

- 各 `deferredEvents` 項目に刻む `stepS03` は、`v41StateDigest` が既に
  `JSON.stringify(g.deferredEvents||[])` を含んでいる（`engine/06:142`）ので**自動的に digest に入る**。
  誘発が積まれている局面の digest は変わるが、**literal な digest を固定している既存テストは 0 件**、
  `data/` に保存済み Replay パッケージも無いので、既存の比較（保存なし ⇔ 再開 ⇔ Replay）はそのまま成立する
- `gameState.procStepS03` 自身は digest に**追記しない**。Action の適用順から決まる導出値であり、
  Journal 再生でも同じ値に再構成される。`timingWindow` を digest に入れない方針（S03-U486 / U489）と同じ扱いで、
  かつ判定に使うのは「刻んだ値と現在値が等しいか」という差分だけなので一致する
- 保存は `gameState` をまとめて直列化するので `procStepS03` も保存に乗る。
  再開直後にだけ値がずれる余地が無いことを、S03-U489 と同じやり方（再開の末尾で実測）で確認する
- `EVENT_QUEUE_V31` の payload に `stepS03` を入れるので、Journal 再生でも同じ値が再現される
- S03-U492 で足した「本当に何かが起きたか」の印（`logIt` の呼び出し回数・遅延イベントを積んだ回数）は
  **状態に入れない**。1 回の `applyAction` の中の差分だけを見るので、保存・digest・Journal には出ず、
  再生では同じ Action 列・同じ reducer を通るので同じ判定になる
- 回帰テストは S03-U484 と同じ 3 本立てにする:
  1. 保存なしで通しで駆動した場合の候補列
  2. 停止点で保存 → 新しい VM で再開した場合の候補列（**1 と一致すること**）
  3. `v44ReplayAuditPackage` の監査（全 digest と最終状態の再現）
  さらに negative control（判定を無効化すると逃さなくなる＝元の挙動に戻る）

## 6. 採らない案

- **カードごとに個別実装する**: 同じ規則が 100 枚以上に散り、保存・再開の一致も個別に壊れる
- **テキストからの自動推定だけで全カードに適用する**: 上記 (B) の理由。根拠の無い挙動変更になる
- **チェーンリンク番号だけで判定する**: R4 の《光神テテュス》08/01/30（チェーン1が「処理なし」なら逃さない）を
  説明できない。判定軸は「最後に行われた処理か」であって、リンク番号ではない。
  実測でも、チェーン2で召喚し**後続リンクが処理なし**（永続罠の発動）の場合は《落とし穴》側が発動できる
- **帳簿の Action を列挙して除外する拒否リスト**（S03-U491 の形）: 列挙の漏れが「誤って逃す」側に落ちる。
  上の (A) で許可リストに反転した
- **召喚成功後の POINT 窓そのものを開かない / 応答候補を全部消す**: 一般のクイックエフェクトまで
  発動できなくなる。逃すのは「召喚成功を条件とする発動」だけで、優先権と応答機会は別の軸である
- **召喚成功後の応答と召喚無効を 1 つの変更にまとめる**: 根拠の裁定が別件（1-a）で、
  無効側は「召喚は成功したが無効にもできない」という別の仕様判断になる。単位を分ける

**採らない案（S03-U493 で足した分）**

- **ログ 1 行を「起きた」の印にする**: 断りをログに書いて何もしない reducer があるので空振りを処理と数え、
  逆にログを書かない処理は数え落ちる。除外リストの語での機械監査も `COUNTER_ADD` の「置けない」を取りこぼした。
  盤面の署名を 1 枚ごとの状態まで広げれば、ログは要らない。
- **配線だけで「召喚成功を条件とする発動」と断定する**: 候補 518 件の全件監査で、「場合」15 件と
  文言が読み取れない 24 件を誤って落としていた。文言を見ずに分けることはできない。
- **カード 1 枚ごとに手で分類した表を持つ**: 518 件を人手で分類すると、根拠の無い分類が静かに混ざる。
  文言の読み取り＋当時裁定による宣言の上書き＋監査の件数固定の組み合わせの方が、根拠を追える。
- **`attacked` / `procedureBaseStats` などの帳簿の欄も署名に入れる**: どの Action でも書き換わるので、
  空振りの Action まで「起きた」と判定して**誤って逃させる**。

**採らない案（S03-U494 で足した分）**

- **テキストの該当句に「できる」が無ければ強制とみなし、一律に逃さない**: 向きは「逃さない」側だが、
  実測 50 組／37 枚に効き、しかもコストを伴う「〜する事で、〜する」の形は現行テキストで「発動できる」に
  改訂されている例がある（《インヴェルズ・モース》）。R1 の宣言は当時裁定が強制と明言している 6 枚に限り、
  残りは 5-a #1-b に**未確定**として残した。
- **`flipSummonReverse` を残したまま「効果で表側にされた場合」へ広げる**: 当時裁定は逆を答えている
  （R8）。広げる前に根拠を確認したので、種別そのものを無効にした。
- **《魔導戦士 ブレイカー》を宣言表に入れる**: 当時裁定 `WIKI-BC4886A97EED` が述べているのは
  「召喚」の意味（R9）であって強制／任意ではない。宣言すると (B-2) の文言判定の negative control
  （文言の判定を外すとブレイカーまで落ちる）が宣言で隠れてしまうので、入れずに R9 の根拠として使った。
- **カード単位の「強制 255 枚」をそのまま R1 の範囲とみなす**: 静的な読み方で、エンジンの実際の判定
  （候補ごと・効果ごとの `triggerCandidateForcedS03`）とは 8 枚ずれる。組単位で数え直した（5-b）。

**採らない案（S03-U496 で足した分）**

- **文言と配線だけで落とし続ける**: 当時の根拠で裏付けられているのは 290 組のうち一部だけで、
  残りの誤りの向きには「正しい発動を潰す」側がある（3(B-4)）。許可リストで公開範囲を絞った。
- **未確定のカードを「逃さない」と宣言表に書く**: 宣言表は当時裁定を根拠に挙動を決める場所であり、
  根拠の無いものを書くと「確定した」ように見える。許可リストに**入れない**ことで従来挙動を維持し、
  5-a #0 に未対応として残した。
- **許可リストをカード名だけで持つ**: 1 つのイベントに複数の効果が配線されているカードでは
  効果別の判定にならない（《アルカナフォースIII－THE EMPRESS》で実測）。
  イベントの配列と、必要なら効果キーで持つ。
- **確認できた範囲を広げるために現行テキストの「できる」だけを根拠にする**: 現行テキストは時代混在で、
  任意性そのものが改訂されている例がある（《インヴェルズ・モース》）。当時裁定の引用か、
  当時裁定が任意性を述べていることを要求した。

**採らない案（S03-U497 で足した分）**


- **既存の `SUMMON_WINDOW_*` に (A) の処理番号の比較を入れる。** 1-c で 4 種別すべてを実測したところ、
  窓が開くのは必ず chain 0 / `procStepS03` 0 の時点だった。比較は一度も成立しないので、
  入れても挙動は変わらず、「召喚無効も逃す」を実装したという**誤った記録だけが残る**。
- **窓を開くかどうかを「保留イベントが空か」で決める。** シンクロ召喚の窓は保留イベント 4 件を抱えて
  開く（素材が場を離れた分）。素材の離脱はシンクロ召喚の手順そのもので、当時裁定の「召喚の後の別の処理」
  ではない。この案だと EX 召喚が常に無効にできなくなる。
- **解決中の召喚をチェーン終了まで遅らせる（(D) 案 (a)）。** 公開済みの (A) の刻み方が変わる。
- **当時裁定の無い経路へまとめて窓を足す。** `R1103-ROACH-003` / `R1103-RAIOH-002` / `R1103-WARNING-006` は
  回答日の無い二次資料の整理であり、`WIKI-2CF23AA42E79`（回答日 2011-08-25）と同じ重みでは扱わない。
  5-a #1-d / #1-e として未対応に残す。

**採らない案（S03-U498 で足した分）**

- **`processChainEndV30` で窓を開いて `PROC_V27_WAIT` で止める**（S03-U497 が第一候補にしていた場所）:
  その関数の残り（`eventChainResumeV11` の続き、`CHAIN_AFTER_V2` の呼び戻し）が飛ぶ。どちらも公開済みの経路。
- **窓の後に `CHAIN_END` をもう一度積む**: `endLinkResolutionS03` を二度通す。
- **印を付けずに「解決中かどうか」で窓を開く**: 同じ `onNormalSummon` を積む《デュアル・サモナー》の
  デュアル再召喚（`GEMINI_SUMMON_S03`）まで巻き込む。あちらは無効のときモンスターを場から取り除いて
  はいけない（召喚前から場に居る）ので、取り消しの形が違う。許可リストにして**印のない経路は従来挙動**にした。
- **解決中の特殊召喚にも同じ窓を開く**: いまの `sc.summonNegate` の `kinds` は
  `normal` / `flip` / `procedure` / `synchro` / `xyz` の 5 つで、効果による特殊召喚の種別が無い。
  新しい種別を足すとカードスクリプト側（公開済み）を全件直すことになり、根拠も `R1103-ROACH-003`
  （**回答日なし**）しかない。5-a #1-d に**未対応**として残す。
- **無効にしたモンスターを `FX_TO_GRAVE`（破壊）で送る**: 召喚は成立していないので「破壊された時」は
  発動しない。既存の kind `normal` の取り消しと同じ `MOVE` に揃えた。
