# 「タイミングを逃す」の設計（共通エンジン課題）

S03-U487 / U488 / U489 が未解決として残した「チェーン2以上で召喚し、その後に別の処理がある場合はタイミングを逃す」を、
カード個別の対処ではなく共通処理として入れるための設計。
**S03-U491 で機構（A)(B)(C) を入れ（宣言 0 件なので挙動は変わらなかった）、S03-U492 で (A) を作り直して
「召喚成功を条件とする発動」1 種別を有効にした。** 他の種別・カードは S03-U493 以降で段階的に行う。

### 1-a. 《血の代償》のページにある 2 件は別のタイミングの話（S03-U492 で訂正）

同じ答えが書かれているため S03-U487 / U491 がこの 2 件を混ぜて引用していたが、**問われているカードが違う**。
`cards` 欄はどちらも「血の代償」だが、これは裁定が載っているページの名前で、発動するカードではない。

| 裁定 ID | 問われているカード | タイミング | 回答日 | 取得日 |
|---|---|---|---|---|
| `WIKI-2B88D7C8D921` | **《落とし穴》**（召喚成功時に発動する罠） | **召喚成功後の応答** | **なし**（本文に日付が無い） | 2011-08-26 |
| `WIKI-2CF23AA42E79` | **《神の宣告》《キックバック》《昇天の角笛》**（召喚を無効にするカード） | **召喚そのものの無効** | **2011-08-25** | 2011-08-26 |

答えはどちらも「チェーン１で行われているならば、発動可能です。 チェーン２以上で行われ、召喚の後に別の処理がある場合は
タイミングを逃す事になり発動できません。」で、`WIKI-2CF23AA42E79` だけが末尾に「(11/08/25)」を持つ。

エンジンでは 2 つは別の場所で実装されている。

- **召喚成功後の応答** — 召喚が成立した後に出る `onNormalSummon` / `onSpecialSummon` / `onFlip`（反転召喚）。
  `collectHandlers`（`engine/40`）が候補を集める。**S03-U492 の対象はこちらだけ。**
- **召喚そのものの無効** — 召喚が成立する前の `SUMMON_WINDOW_OPEN_V42` …
  `summonNegatorsV2` / `beginSummonWindowV2`（`engine/30`）。**S03-U492 では触らない。**
  ここを逃す形にすると「召喚は成功したが無効にもできない」という別の仕様変更になるため、
  裁定（回答日 2011-08-25）と実装の対応だけ記録して別単位に回す。

S03-U487 の注釈はこの 2 件を《奈落の落とし穴》《神の角笛》と誤って書き、片方の回答日を両方に付けていた。
S03-U492 で注釈を訂正した（カード名・回答日の有無とも）。

### 1-b. 「血の代償自身が逃す」ではない

この 2 件で逃すのは**応答する側のカード**（《落とし穴》等）であって、《血の代償》ではない。
《血の代償》の効果は誘発効果ではなく、チェーンブロックを作って通常召喚を行う起動相当の効果なので、
宣言表にも種別にも入らない。

## 3. 設計

### (A) 処理番号 `procStepS03` — S03-U492 で作り直した

`gameState.procStepS03` は「**行われた処理**」の通し番号。`applyAction` の最上位の適用で、次の 3 つが
揃ったときだけ 1 進める（`engine/1ZZX` の `missedTimingBeginS03` / `missedTimingEndS03`、`engine/00:216`）。

1. その Action の種類が**許可リスト** `MISSED_TIMING_PROCESSING_S03` にある
2. 適用が**例外で終わっていない**
3. その適用の中で**本当に何かが起きた** — 次のどれか。
   - **盤面の署名**（各ゾーンの枚数とライフ）が変わった
   - 条件が満たされた**遅延イベントが積まれた**
   - **`logIt` が書かれた**（ただし下の除外あり）
   署名も呼び出し回数も 1 回の `applyAction` の前後でしか比べないので状態に入れず、保存・digest にも出ない
   （`gs.log` は 60 件で打ち切られるので長さでは数えられない）。

**ログを印にできない Action**: 許可リストの一部の reducer は「適用できなかった理由」をログに書いて
何もせずに終わる（`モンスターゾーンが一杯です`、`このターンは既に通常召喚しています` 等）。
ログだけを印にすると**空振りを処理と数えてしまい、誤って逃させる**ので、
この 10 種（`NORMAL_SUMMON` / `SET_MONSTER` / `SET_ST` / `TOKEN_CREATE` / `FX_SPECIAL_SUMMON` /
`FX_EX_SUMMON` / `FX_RITUAL_SUMMON` / `FX_OVERLAY` / `FX_DETACH` / `FX_MONSTER_EQUIP_V46`）は
署名の変化だけで判定する（成功時は必ずカードかライフが動く）。
この一覧は engine のソースから機械的に監査しており、他の許可リストの Action に断りのログが足されれば
テストが落ちる。

**残っている取りこぼし（安全な側）**: 盤面の枚数もライフも変えず、イベントも積まず、ログも書かない
処理（表示形式の変更だけ、攻守やレベルの増減だけ、カウンターの増減だけ）は、ログが書かれなければ
数えられない。その場合は「逃すべきものを逃さない」＝ S03-U491 以前の挙動になる。

#### S03-U491 の拒否リストが誤りだった理由（実測）

S03-U491 は逆向きで、「帳簿の Action を 39 種列挙して除外し、それ以外では進める」拒否リストだった。
当時の設計書は「取りこぼしても『逃さない』＝現状維持側に倒れるので安全」と書いていたが、**これは逆**である。
除外リストの漏れは**番号を進めてしまう**ので、刻んだ値と現在値が食い違い、**誤って逃させる**側に落ちる。

S03-U492 の実測でその欠陥が実際に出た。《血の代償》がチェーン１で通常召喚した場合
（`WIKI-2B88D7C8D921`: **《落とし穴》を発動できる**）でも、召喚と遅延イベントの取り出しの間に
`SPECIAL_WIN_DEFER_S03`（勝敗の確認）が 1 回走り、番号が **3 → 4** とずれていた。
S03-U491 で宣言が 0 件だったため対局には出ていなかったが、宣言を入れればその瞬間に正しい発動を潰していた。

許可リストなら**表に無い Action は番号を進めない ＝ 逃さない ＝ 現状維持**なので、漏れは安全な側に落ちる。
その代わり許可リストは不完全であり、**実際には「別の処理」なのに数えていない Action があり得る**。
その場合は「逃すべきものを逃さない」＝ S03-U491 以前の挙動になる。これは意図した倒し方で、
対局が壊れない側である。表は宣言を増やすたびに実測で足していく。

#### 同時に行われた処理（R4）

同時処理が**別々の Action で実装されている**場合に誤って逃させないか実測した。

| 実測した経路 | Action | 刻み |
|---|---|---|
| 《激流葬》でモンスター 2 体を破壊 | `FX_WIPE_ZONE` ×2（2 つめは空振りでログ無し） | 3 件の `onLeaveField` すべて同じ番号 |
| 戦闘で攻撃側・守備側が相打ち | `BATTLE_CLEANUP` 1 回 | 2 件の `onLeaveField` が同じ番号 |
| 同一解決中の複数特殊召喚 | `flushResolutionSummonBatchV2` が 1 イベントにまとめる | 1 件なので番号は 1 つ |
| 《光帝クライス》の破壊 → ドロー（S03-U491 の試験） | 破壊とドローは別々の Action | 番号が進む（**逃す側が正しい**。R4 の《ZERO－MAX》10/02/21） |

空振りの Action（対象がもう場に無い `FX_WIPE_ZONE` 等）は上の条件 3 で弾かれる。

### (B) 判定の対象 — 宣言（カードごと）と種別（構造）

**(B-1) 宣言 `MISSED_TIMING_DECL_S03`**（`engine/1ZZX`）: カード名 → `{mode:'miss'|'never', ruling:'WIKI-…'}`。
`never` は R5 の例外カード。各件に当時裁定の ID を必ず添える。
カードテキスト（`data/carddata.json` の `e`）からの自動推定は**採らない**。DB のテキストは時代が混在しており
（《代打バッター》は現行の「①:…時に発動できる」、《E・HERO The シャイニング》は当時の文面）、
推定の誤りが静かに対局を変える。

**(B-2) 種別 `MISSED_TIMING_CLASSES_S03`**: カードのテキストではなく、**エンジンがその候補をどの経路で拾ったか**で
決まる構造的な分類。S03-U492 で有効にしたのは 1 種別だけ。

- `summonSuccess` — 「召喚・反転召喚・特殊召喚に成功した時」が発動条件になっている発動。
  `collectHandlers` が `onNormalSummon` / `onSpecialSummon` / `onFlip`（`evt.flipSummon` が真のときだけ）で
  拾った候補がこれに当たる。召喚されたモンスター自身の召喚誘発（《E・HERO エアーマン》等）と、
  相手の召喚に反応する罠（`onOtherSummon`。《落とし穴》《奈落の落とし穴》《激流葬》等）の両方を含む。
  テキストを読んでいないので推定の誤りが入らない — 「召喚成功を条件に発動している」ことは配線から確定する。

宣言と種別の関係: `never` の宣言は種別より強い（R5）。`miss` の宣言はイベントを問わず逃す。
宣言も種別も無い発動は**判定しない**（＝現状維持）。

### (C) 判定は `collectHandlers` の 1 箇所

誘発候補を 1 件落とす条件（`missedTimingDropS03`）:

1. その誘発の元イベントに `stepS03` が刻まれている（刻みの無い `emitEvent` 直接呼び出しと古い保存は判定しない）
2. 刻まれた `stepS03` が、いま提示しようとしている時点の `gameState.procStepS03` と**異なる**（R2 / R4）
3. そのカードが `never` と宣言されて**いない**（R5）
4. そのカードが `miss` と宣言されている、**または**種別に当てはまる（B-2）
5. その候補が**強制ではない**（`triggerCandidateForcedS03(c) === false`、R1）

**通常の優先権・応答機会には触らない。** 召喚成功後の POINT 窓（`summonFast` / `flipFast`、
`pointResponsesV27` → `getChainResponsesV2`）はそのまま開き、一般のクイックエフェクトは
チェーン終了後に今までどおり発動できる。実測でも、チェーン2の召喚で《落とし穴》側が落ちた後も
POINT 窓には《血の代償》（クイックエフェクト）が出ていた。

落とした候補は診断用の `MISSED_TIMING_DROPS_S03` に残す（digest にも保存にも入れない）。
落とした結果候補が 0 件になれば、`emitEvent` は `false` を返して従来どおり次へ進む。

## 4. 保存・再開・Replay

- 各 `deferredEvents` 項目に刻む `stepS03` は、`v41StateDigest` が既に
  `JSON.stringify(g.deferredEvents||[])` を含んでいる（`engine/06:142`）ので**自動的に digest に入る**。
  誘発が積まれている局面の digest は変わるが、**literal な digest を固定している既存テストは 0 件**、
  `data/` に保存済み Replay パッケージも無いので、既存の比較（保存なし ⇔ 再開 ⇔ Replay）はそのまま成立する
- `gameState.procStepS03` 自身は digest に**追記しない**。Action の適用順から決まる導出値であり、
  Journal 再生でも同じ値に再構成される。`timingWindow` を digest に入れない方針（S03-U486 / U489）と同じ扱いで、
  かつ判定に使うのは「刻んだ値と現在値が等しいか」という差分だけなので一致する
- 保存は `gameState` をまとめて直列化するので `procStepS03` も保存に乗る。
  再開直後にだけ値がずれる余地が無いことを、S03-U489 と同じやり方（再開の末尾で実測）で確認する
- `EVENT_QUEUE_V31` の payload に `stepS03` を入れるので、Journal 再生でも同じ値が再現される
- S03-U492 で足した「本当に何かが起きたか」の印（`logIt` の呼び出し回数・遅延イベントを積んだ回数）は
  **状態に入れない**。1 回の `applyAction` の中の差分だけを見るので、保存・digest・Journal には出ず、
  再生では同じ Action 列・同じ reducer を通るので同じ判定になる
- 回帰テストは S03-U484 と同じ 3 本立てにする:
  1. 保存なしで通しで駆動した場合の候補列
  2. 停止点で保存 → 新しい VM で再開した場合の候補列（**1 と一致すること**）
  3. `v44ReplayAuditPackage` の監査（全 digest と最終状態の再現）
  さらに negative control（判定を無効化すると逃さなくなる＝元の挙動に戻る）

## 6. 採らない案

- **カードごとに個別実装する**: 同じ規則が 100 枚以上に散り、保存・再開の一致も個別に壊れる
- **テキストからの自動推定だけで全カードに適用する**: 上記 (B) の理由。根拠の無い挙動変更になる
- **チェーンリンク番号だけで判定する**: R4 の《光神テテュス》08/01/30（チェーン1が「処理なし」なら逃さない）を
  説明できない。判定軸は「最後に行われた処理か」であって、リンク番号ではない。
  実測でも、チェーン2で召喚し**後続リンクが処理なし**（永続罠の発動）の場合は《落とし穴》側が発動できる
- **帳簿の Action を列挙して除外する拒否リスト**（S03-U491 の形）: 列挙の漏れが「誤って逃す」側に落ちる。
  上の (A) で許可リストに反転した
- **召喚成功後の POINT 窓そのものを開かない / 応答候補を全部消す**: 一般のクイックエフェクトまで
  発動できなくなる。逃すのは「召喚成功を条件とする発動」だけで、優先権と応答機会は別の軸である
- **召喚成功後の応答と召喚無効を 1 つの変更にまとめる**: 根拠の裁定が別件（1-a）で、
  無効側は「召喚は成功したが無効にもできない」という別の仕様判断になる。単位を分ける
