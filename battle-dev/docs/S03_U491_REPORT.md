# S03-U491 — 「タイミングを逃す」の共通機構（段階 1：宣言 0 件）

ユーザー指示の 2 番。S03-U487 / U488 / U489 が未解決として残していた
「チェーン2以上で召喚し、その後に別の処理がある場合はタイミングを逃す」を、
カード個別の対処ではなく共通処理として入れる。設計は `docs/S03_MISSED_TIMING_DESIGN.md`、
当時裁定 123 件の抽出は `docs/S03_MISSED_TIMING_RULINGS.md`。

**本単位ではカードの宣言を 1 件も入れていないので、対局の挙動は変わらない。**
機構を入れ、保存・再開・Replay で判定が一致することを固定するところまで。

## 1. 入れたもの

新しい共有モジュール `engine/1ZZX_missed_timing_s03.js`（`build_manifest.json` の
`1ZZW` と `ui/10` の間に配線）。

### (A) 処理ステップ番号 `gameState.procStepS03`

`applyAction`（`engine/00:215`）の**最上位の適用 1 回を 1 ステップ**とする単調増加カウンタ。

- 1 回の `act()` の中で起きたことは「同時」なので、そこで積まれた誘発は互いを逃させない（**R4**）
- 解決の途中で別の `act()` が走れば、先に積まれた誘発は「その後に処理があった」ことになる（**R2**）
- チェーンの残りリンクの解決は多数の `act()` を伴うので **R3** は自動的に満たされる
- 帳簿・提示・掃除の Action 39 種（`MISSED_TIMING_BOOKKEEPING_S03`）はステップを進めない。
  迷ったものは「進めない」側に置いた — 進めないほうが「逃さない」＝現状維持に倒れるため安全

> **S03-U492 で訂正**: 上の最後の行は、**表に入れたもの**については正しいが、
> 「拒否リストだから取りこぼしても安全」という一般化が**誤り**だった。
> 列挙の漏れは番号を進めてしまうので、刻みと現在値が食い違い、**誤って逃させる**側に落ちる。
> 実測で《血の代償》チェーン１（当時裁定では《落とし穴》を発動できる）でも
> `SPECIAL_WIN_DEFER_S03` が割り込んで番号が 3 → 4 とずれていた。宣言が 0 件だったので
> 対局には出ていなかったが、宣言を入れればその瞬間に正しい発動を潰していた。
> S03-U492 で**許可リスト**に反転し、空振り・例外も進めないようにした。
> 詳細は `docs/S03_U492_REPORT.md` の 3 と `docs/S03_MISSED_TIMING_DESIGN.md` の 3(A)。

### (B) カードごとの宣言 `MISSED_TIMING_DECL_S03`

`'miss'`（時の任意効果として逃す）/ `'never'`（例外カード等）。
**宣言の無いカードは `'never'` と同じ**。カードテキストからの自動推定は行わない
（`data/carddata.json` の文面は時代が混在しており、推定の誤りが静かに対局を変える）。
**本単位の宣言は 0 件**で、各件には当時裁定の ID を必ず添える方針。

### (C) 判定 `filterMissedTimingS03`

判定は `collectHandlers`（`engine/40:1990`）の戻り値 1 箇所だけで行う。候補 1 件を落とすのは次が揃うとき:

1. その誘発の元イベントに刻まれた `stepS03` が、いまの `gameState.procStepS03` と異なる
2. その候補が**強制ではない**（既存の `triggerCandidateForcedS03`、S03-U44 をそのまま使う ＝ **R1**）
3. そのカードが `'miss'` と宣言されている（**R2 / R5**）

刻みの無いイベント（`emitEvent` の直接呼び出し、S03-U490 で数えた 7 箇所）と、
本単位より前の保存データは判定しない（保守的に「逃さない」側）。

### 刻み

`queueDeferredEventV2`（`engine/30:1841`）が、積むときの `procStepS03` をイベントに刻む。
`deferredEvents` は `v41StateDigest`（`engine/06:142`）に入っているので、
刻みは**自動的に digest に入り**、`EVENT_QUEUE_V31` の payload にも乗るので Journal 再生で再現される。
`procStepS03` 自身は digest に追記していない（Action の適用順から決まる導出値で、判定に使うのは差分だけ）。

## 3. あわせて直した集計の誤り（「タイミングを逃す」とは別件）

`scripts/finish-work.ps1` は PASS / FAIL を `-Pattern '\bFAIL\b'` で数えていた。
PowerShell の `Select-String` は既定で**大文字小文字を区別せず、行のどこでも**一致するので、
日本語の判定文の中にある英単語を失敗として数えていた。S03-U490 の試験でこの偽の件数が **6** になった
（ゲート本体の行頭 `FAIL` は 0。`tools/gate_verify.py` と突き合わせて確認した）。

ゲートの規約と同じ**行頭・大文字小文字を区別**して数えるようにし、
緩い件数は `(plus N in-line mentions, not failures)` として別に出す（隠さない）。
`gate_verify.py` を入れた S03-U490 と同じ「集計方法の誤り」なので本単位でまとめて直した。
この修正は `build_manifest.json` に入らないファイルなのでゲートの対象外だが、
試験ブロック G で中身を固定しており、修正を戻すと 3 件すべて落ちることを実測した。
