基点: `claude/work` `cd55f5fd`（U470 part C）。記録された基点ゲート: **22505 PASS / 0 FAIL / GATE_EXIT=0**（直列）。ユーザー指示で同一ツリーの全体ゲートは繰り返さず、変更ごとに専用・近接テストで確かめ、単位の最後に直列ゲートを1回だけ実行した。共有エンジンの変更（Opus が設計・検証済みの事実に基づく実装。設計は変えていない）。単一ライター、`claude/work` のみ。

## 設計（実装したもの）
欠陥: 発動準備は 表にする/手札から置く → コスト → 対象選択 の順に進む。対象選択が「選択できるカードが足りません」で失敗しても `requestChoiceV49` が `false` を返すだけで、`API.selectCard` はその戻り値を捨てる（約1444箇所の呼び出し）ため継続（`finishPrepare` / `opts.onAbort`）が呼ばれず、コストは払われたまま、カードは魔法・罠ゾーンに表で残った。手動キャンセルも同じ停止状態だった。

実装（新規 `engine/1ZZV_prep_tx_s03.js` + 既存エンジンへの数行の接続）:
1. **開く**: 最初の状態変化（表にする = `FX_SET_STATE` / 手札から置く = `MOVE`）の**前**に `PREP_TX_BEGIN_S03` を Journal へ載せる（`commitAutomaticActionV44`: Journal に載り Undo の区切りは増やさない）。reducer は `gs.prepTxS03` に**復元点を1つだけ**置く。gameState の中にあるので Save/Load・Undo/Redo・Replay が自動で運ぶ。手札からの発動は呼び出し元（`duelActivateFromHand` / `duelActivateResponseV2`）が MOVE の前に開き、`prepareDuelActivation` は同じ uid なら再利用する。
   - 復元点は gameState の複製1つ。除外（復元しない）: `prepTxS03` 自身（再帰しない）・`log`（追記のみ）・Journal の連番（`__v41Seq`）・`chain` と優先権の窓・processor・戦闘/召喚の進行・手番/フェイズ・`choiceSeq`。それ以外（`players` = カードの位置・表裏・フラグ・カウンタ・LP・各山、`rngState`、予約/遅延イベント、`runtimeEffects`、発動途中バッファ、選択待ち、回数制限や1ターン1度のフラグ 等）は全部戻る。
   - `players` はプレイヤーの入れ物も**カードのオブジェクトも同じ uid なら同一のまま**中身だけを書き戻す（イベント選択 `EVT_V2_STATE` などの実行時の表がカード参照を持つため。別オブジェクトにすると大天使クリスティアの強制誘発で再提示が壊れた）。
   - digest には開いている間だけ `PTX<uid>:<復元点を取った時点の標準 digest>` が追記される（空なら既存 digest は不変）。
2. **失敗の明示的な合図（推測しない）**: `requestChoiceV49` が候補不足で断った時だけ `CHOICE_INSUFFICIENT_SEQ_S03` が進む。`API.selectCard` はその結果（`false`）を返すようになった。`chooseTargets` は `selectTargets` の前に印を取り、**合図が進んでおり、選択待ちが無く、確認シートも無い時だけ**中止する。同じ見張りをコストの段、COST_SELECTION_FIRST、P1.1 の `activationV11`、および**選択に答えた直後の続き**（コスト後の対象選択が断られる形）にも置いた。合図は**その準備の uid の窓の中でだけ**見る（開いたままの別の記録は巻き戻さない）。「コールバックが来ない」「`pendingChoice` が無い」だけでは中止しない（テストで固定）。
3. **手動キャンセルは別の理由**: `cancelChoiceV49` が発動準備中の選択（`meta.activationPrepS03`）なら理由 `'cancel'` で中止する。候補不足の合図は進まない。
4. **単一の中止**: `PREP_TX_ABORT_S03` が復元点から戻して記録を消す。冪等（記録が無ければ何もしない、uid が違えば触らない、チェーン長が復元点と違えば＝コミット後なので戻さない）。同じ準備では1回しか走らない（関数の戻り値・Journal 件数・reducer 単体で固定）。理由は `insufficient` / `cancel` / `cost-fail` / `refused` / `p11-abort`。
5. **境界は CHAIN_ADD**: `CHAIN_ADD` の reducer が記録を消す（チェーンリンクができた時点で閉じる）。以後の不発・無効でコストは返らない（テストで固定）。中止は `finishPrepare` が中止済み（記録が無い）の準備にチェーンリンクを作らないよう守る。
   - **ブリーフとの違い（1点）**: 「CHAIN_ADD 時に `PREP_TX_COMMIT_S03` を emit」ではなく、CHAIN_ADD の reducer 自身が記録を閉じる（原子的。Journal の件数を増やさない）。`PREP_TX_COMMIT_S03` は「巻き戻さずに記録だけ閉じる」場合（下の 永続魔法の設置）にだけ使う。
6. **Part C は維持**: U470 の `condition` の事前確認は一切変えていない（一度公開された隠し情報は盤面・コストを戻しても取り消せないため）。

接続した箇所: `engine/00`（reducer 3 case と CHAIN_ADD）、`engine/06`（digest、Undo/Redo/読込後に実行時の対応表を状態から作り直す）、`engine/09`（合図、キャンセル／回答の続き）、`engine/10`（`abortPreparedActivationV11`）、`engine/30`（`prepareDuelActivation` / 手札経路 / `commitPreparedActivationV11`）、`engine/40`（`selectCard` の戻り値）。

## 保証の境界（平易に）
**戻るもの**: 発動準備の最初の状態変化から中止までに gameState のうち上記の対象で起きた変化。カードの位置・ゾーン・表裏・設置時の状態、LP、コストで触った山（手札・墓地・デッキ・除外・エクストラ）、1ターン1度などの使用フラグ・回数制限の状態、発動途中のバッファ、予約/遅延イベント、乱数列、選択待ち。Replay は同じ reducer を適用するので同じ結果になる。
**戻らないもの**: (1) すでに公開された情報（見せた・めくったカードを相手が見た記憶、UI の表示、トースト）— だから U470 の事前確認を残している。(2) ログと Journal（追記のみ。中止の1行と ABORT が載る）。(3) チェーン・優先権の窓・processor・戦闘/召喚の進行（準備は触らない。触れていたらチェーン長の不一致で中止自体を拒否する）。(4) **CHAIN_ADD 以後**: チェーンリンクができた後の不発・無効・対象消失ではコストは返らない（ルールどおり。記録は CHAIN_ADD で閉じている）。**コストの払い戻しは CHAIN_ADD で止まる**。既存のチェーンリンクと、それ以前の正当な操作は、どの中止でも触られない。
**範囲外（今回戻らない経路）**: MANUAL モード（`runEffect`、engine/60・70 の `askChain` 経路）の legacy 準備。Journal が切り詰められた保存の読込（S03-U35 のテストが「巻き戻さない」を固定しているため、記録は状態に残るが停止状態は従来どおり）。登録済み（registry）の継続の内部で後から起きる候補不足（カード自身が `abortPreparedActivationV11` を呼ぶ場合は戻る）。
**Undo の意味**: 中止の後に Undo すると、直前の `act()` の手前（`BEGIN` の直後で記録が開いた点、または選択が開いた点）へ戻る。キャンセルの Undo は対象選択に戻り、もう一度キャンセルすれば再び発動前へ戻る（実行時の対応表を状態から作り直す）。Redo は中止後の状態にそのまま戻り、中止を再実行しない。Redo は従来どおり Journal を作り直す（既存の挙動）。

## 代表例（フェーズ1）の結果
- **コストなし — 元の再現**（リビングデッドの呼び声 × メタルシルバー・アーマー）: U470 で `condition` が先に断るようになったため、テスト内だけで修正前の `condition` を戻して「発動が始まってから候補が0」の形をエンジン側で作った。修正前 `{chain:0, sz:1, face:up}` → 今は **罠は裏のまま、墓地・盤面・乱数まで含めて digest が発動前と完全一致**、Journal は `BEGIN, FX_SET_STATE, ABORT(insufficient)` の3件、トースト「選択できるカードが足りません」、チェーンも選択も無い。アーマーが居なくなれば同じ罠が最後まで動く（記録は CHAIN_ADD で閉じる）。実カード（U470 が直していない約119枚の一部）: デモンズ・チェーン（罠）、突進、『攻撃』封じ — 同様に戻る。
- **コスト支払い済み — 洗脳－ブレインコントロール（800LP）**: 修正前 LP 7200・カードは魔法・罠ゾーンに表で残る → 今は **LP 8000・カードは手札・digest が発動前と一致**（Journal は `BEGIN, MOVE, LP, ABORT`）。対象に取れるモンスターがある盤面では同じカードが800LPを払って最後まで動く。早すぎた埋葬（800）・自律行動ユニット（1500）も同様。合成カード（1000LP + 手札1枚を捨てる）も LP・捨てた札・手札の並び・墓地まで全部戻る。
- **手動キャンセル**: 罠は裏に戻り、手札の魔法は手札に戻る。Journal は `CHOICE_CANCEL_V49, PREP_TX_ABORT_S03:cancel`、**候補不足の合図は進まない**ので区別できる。キャンセル後にまた発動でき、コスト支払い後のキャンセルでも LP・捨てた札が戻る。
- **既にチェーンに乗ったリンクは中止の影響を受けない**: 洗脳（P0）がチェーン1にあり、P1 が罠で応答して対象選択が断られても、応答だけが戻り、リンク1・P0 の800LP・その後の解決は変わらない。

## 広げた範囲（フェーズ2）— 何がカバーされ、何がされないか
サーベイ（`survey` 一時スクリプト）: 対象を取る魔法・罠 **969 枚**を、盤面A（アーマー）/A2/C（オベリスク）と対照で発動。修正前（`cd55f5fd` のクリーンコピー）で「発動が始まったが、チェーンも選択待ちも無く、表で魔法・罠ゾーンに残った」のは **128 枚**（免疫が原因 115 + 免疫なしでも起きる 13）。今のビルドでは **4 枚**だけ（下の「設計どおりの永続魔法」）。124 枚は発動前に戻る。
- **カバーされる**: legacy `selectCard` 経由の対象選択・コスト選択の候補不足（`insufficient`）、手動キャンセル（`cancel`）、`cost` が `done(false)`（`cost-fail`）、P1.1 の `activationV11` 内の候補不足と登録済み選択のキャンセル（`p11-abort`）、置いた後の合法性判定で通らない通常/速攻/装備魔法（`refused`）。モンスター効果（場・墓地・手札からの `prepareDuelActivation`）も同じ。
- **カバーされない**: 上の「範囲外」。および、`condition` が通って発動が**始まる**こと自体（UI で一瞬表になって戻る）— 事前に断る U470 の方式の方が隠し情報の面では良いので、中央版 A（下）が残る。
