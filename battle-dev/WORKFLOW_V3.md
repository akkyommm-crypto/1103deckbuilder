# Sonnetへの委譲拡大 v3（2026-10-03・ユーザー承認済み）

## 適用
ユーザーは、通常の実装・失敗調査・修正・全体検証・引継ぎ作成をSonnetへ広げ、共通エンジン・裁定・テスト期待値の判断はOpusに残す運用を承認した。
比較ラベルは `workflow_profile: delegation-expanded-v3`。従来の分担と混ぜない。
これは役割分担の更新であり、元の受入基準や公開条件の緩和ではない。

進行中の子エージェントやゲートは中断しない。既存単位は従来条件で完結させ、次の新規単位から適用する。
今の作業ツリーや検証対象を他者が変更している間にCLAUDE.md等を差し替えない。
次の新規ツリーを作る安全な区切りで、このパッケージの変更を取り込む。既存規約の新版があれば丸ごと上書きせず差分を統合する。
進行中に混在した単位は `workflow_profile: transition-mixed` とし、旧版・新版の比較から分ける。

## 担当
### Sonnet / battle-implementer
- 既存APIを利用するカード実装、専用・近接テスト、negative control、通常の失敗調査と修正まで完結する。
- 受入条件を満たした通常カードの宣言、テスト登録、監査、事前スキャン、全体ゲートも、指定された単位ツリーで担当する。
- ゲートは既存スクリプトで実行する。正常ログ全文は保存し、終了コード・件数・失敗箇所・対象hashだけを短く返す。
- 報告、測定記録、公開用の下書きまで作る。機械処理の集計をOpusへ戻さない。
- 同じ修正仮説が2回失敗した場合や共通エンジン・裁定・保存/Replayの問題は、再現・失敗箇所・試行済み案を添えてOpusへ返す。
- 既存テストの期待値変更・削除・skipで合格させない。必要性がある場合は根拠を整理してOpusに判断を戻す。新規テストでも、失敗後に期待結果を都合よく変えない。

### Opus / メイン
- 最初に対象・受入条件・変更範囲・参考実装・ゲート担当を短く固定して渡す。
- 共通エンジン、裁定が不明な処理、同時処理、保存/Replay、既存テストの期待値変更、Sonnetが解けない不具合を扱う。
- 通常の返却は、短い要約、差分一覧、対象hashに対応するゲート結果、変更した効果とテストの重要箇所を確認する。全ソースの再読・全テストの重複実行・正常な成果の再実装を標準手順にしない。
- 難所を解決したら、残りの通常修正と再検証をSonnetへ戻す。ログ全文・引継ぎ書の清書・定型的なファイル操作を引き取らない。
- 重大変更や検証の不足があれば必要範囲を詳しく確認する。時間短縮のためにレビューや必須検証を省略しない。
- 最終の受入・公開、共有LATEST更新は従来どおりメインだけが行う。Sonnetは共有正本を更新しない。

## ゲートと書き手
一つのツリーには実装writer一人、ゲート担当一人。通常はSonnetが両方を順番に担当する。
親は、委譲中の同じツリーのソース・dist・宣言・報告を書き換えない。子が全体ゲートを開始したら親は重複起動しない。
実行中のゲートの入力を固定する。結果返却には対象ソース/成果物hashとログを含める。
終了コードはテスト直後の値を保存する。後続echoの成功やPASS数だけで合格としない。
ゲート合格後に対象コードが変われば、その変更に必要な検証を再実行する。既知例外・PASS差分・監査条件は現行規約を維持する。
問題のあるカードだけを保留し、独立した通常作業は続行する。ただし共有競合、ユーザー停止、実行不能な利用制限では停止・引継ぎを行う。

## 指示と返却を短くする
指示：単位ID、基点hash、ツリー、対象・受入条件、変更可能ファイル、参考実装1〜2件、必須検証、ゲート担当、公開はメイン。
返却：対象・変更点、変更ファイル、基点/最終hash、専用/近接/対照/監査/スキャン/全体ゲートの結果とログ場所、既知例外、未解決点、実測値。
子に渡す指示書へ旧版の「全体ゲートは親が担当」「宣言・報告は親へ戻す」を再コピーしない。
別ディレクトリで開いたメインから委譲する場合も、このv3の役割・ゲート担当・中止条件を短く伝える。設定が読み込まれたと仮定しない。
実際のモデル・effortを記録する。定義のmediumと実行ログのhighが違えば実測を採用する。比較のために他条件も同時に変えない。

## 比較
1単位1JSON。`mode: mixed`, `workflow_profile: delegation-expanded-v3` と記録する。
まず同程度の通常作業3件を、共有完了まで観測する。旧分担、委譲拡大版、Opus単独は別集計。
Opus単独への切替を自動的に行わない。子を回収してから、別途指定された切替を適用する。
親子・再試行・手戻りを含める。取得できない値はnull。失敗単位も消費に含める。架空の節約率を報告しない。
利用枠の開始/終了値が得られる場合だけ記録する。枠のリセットや他作業混入があれば単純差分を節約の根拠にしない。
難度/category、受入基準、推論強度が違うものを同列比較しない。比較のために同じ実装を二重に行わない。

## 稼働中セッションへの反映
このファイルを置いただけでは、稼働中のClaudeが新しい指示を受け取ったことにはならない。
メインがこの更新を読み、次の単位の指示書に新しいゲート担当が書かれた時点を適用開始とする。
適用開始の単位IDと時刻を測定記録に残す。開発コード・モデル権限・認証・利用枠・hooksは、この更新では変更しない。
